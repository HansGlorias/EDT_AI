# EDT AI — задание

## Что это и зачем

Плагин для 1C:EDT, который добавляет в IDE чат с языковой моделью и (в
следующих этапах) даёт модели инструменты через MCP. Целевое использование —
в том числе закрытый контур (КСПД): модель доступна по внутреннему адресу,
TLS через корпоративный CA, интернета нет.

Репозиторий публичный: адреса, токены, имена хостов и сертификаты из КСПД
сюда не попадают ни в код, ни в тесты, ни в README.

## Целевые окружения

| Окружение | EDT | Eclipse | ОС / UI |
|---|---|---|---|
| Рабочая машина | 2026.1, 2025.2 | 4.30 (2023-12) | Windows 10/11, win32 |
| КСПД | 2024.2.6 | 4.30 (2023-12) | Astra Linux 1.8, GTK 3 |

Все три версии EDT собраны на Eclipse 4.30, Java 17 (для 2024.2.6 проверено по
логу установки на Astra). Если появится EDT на другом Eclipse, target platform
опускается до него.

В КСПД EDT стоит в `/opt` от root, sudo у пользователя нет. Установка через
Install New Software в пользовательский профиль p2 падает на компоненте 1C:Link
(chmod на отсутствующий nginx), то есть не работает для любого плагина. Поэтому
есть обходной путь без p2: `tools/edtai-user-install.sh`, подробности и что может
исправить администратор — в `docs/install-astra.md`.

## Архитектурные решения

- **Только Eclipse 4.30.** Target platform — релиз 2023-12, собираем
  против него. API новее 4.30 не используем. Нижние границы версий в
  `Require-Bundle` ставим не выше 4.30.
- **Java 17.** `Bundle-RequiredExecutionEnvironment: JavaSE-17`.
- **Без SWT Browser.** На Astra нет гарантированного WebKitGTK, на Windows
  Edge/IE ведут себя по-разному. Весь UI — обычный SWT/JFace.
- **Сертификаты.** Поддерживаем корпоративный CA: системное хранилище ОС
  (на Windows `Windows-ROOT`) плюс дополнительный PEM-файл. Отключить
  проверку сертификатов нельзя.
- **Токен — только в Eclipse Secure Storage.** В обычных preferences и
  логах токена нет.
- **Ядро без UI.** `core` не зависит от SWT/JFace и тестируется headless.
- **Без сторонних библиотек.** Только JDK 17 и то, что есть в платформе
  4.30. В КСПД плагин ставится скриптом `tools/edtai-user-install.sh`: он
  дописывает в `bundles.info` EDT все `plugins/*.jar` из zip, без p2. Чужой
  бандл (gson, Jackson, MCP SDK) может уже быть в EDT в той же или другой
  версии, и разрешить конфликт без p2 некому — сломается только в КСПД.
  Поэтому JSON, разбор SSE, Markdown и клиент MCP пишем сами в `core`, с
  тестами. Новые бандлы плагина (`io.github.hansglorias.edtai.*`) скрипт
  подхватывает сам.
- **HTTP — `java.net.http.HttpClient`** (модуль JDK, OSGi-импорт не нужен),
  HTTP/1.1, прокси — `ProxySelector.getDefault()`. EDT должна работать на
  JRE с модулем `java.net.http` — первый пункт ручной проверки.
- **API самой EDT** (`com._1c.g5…`) в target platform нет. Контекст берём
  через обычный Eclipse API (`ITextEditor`, `IDocument`, `IFile`) и
  структуру каталогов проекта (`src/CommonModules/<Имя>/Module.bsl`).
- **Лента чата — один `StyledText`** со стилями и ссылками-действиями, а не
  виджет на сообщение: одинаково на GTK и win32, выделение через несколько
  сообщений, дешёвый стриминг. Подтверждения вызова инструментов — панелью
  над полем ввода. Цвета — из темы JFace, не зашиты.

## Как проверяем UI

- **Автотесты в живом workbench** без SWTBot: тест обращается к виджетам
  вида напрямую (package-private геттеры).
- **Логика — в `core`.** Всё, что можно проверить без SWT (клиент модели,
  разбор потока, состояние диалога, позже — разбор Markdown в «текст +
  стили»), тестируется headless.
- **Фейковый сервер модели** в тестах: свой HTTP-сервер на `ServerSocket`
  без зависимостей. Отдаёт SSE частями, ошибки, «зависание», HTTPS со
  сгенерированным тестовым сертификатом для `localhost`.
- **Скриншоты под xvfb.** UI-тесты сохраняют PNG вида в
  `tests/*/target/screenshots/`, CI выкладывает их артефактом
  `screenshots-<ОС>` с Ubuntu (GTK 3) и Windows. С эталонами попиксельно не
  сравниваем — шрифты на машинах разные; скриншоты для просмотра глазами
  при ревью, проверки в тестах — по состоянию виджетов.

## Этапы

### Этап 1. Каркас — готово

Вид «AI Chat» с эхо-провайдером, страница настроек (протокол, адрес,
модель, токен в Secure Storage, сертификаты, MCP-серверы), тесты, CI на
Ubuntu и Windows, zip update-site, установка в КСПД скриптом.

### Этап 2. Подключение к модели и стриминг — готово

Чат отвечает настоящей моделью, ответ появляется по мере генерации, запрос
можно остановить, ошибки понятны без чтения логов.

Состав:

1. **JSON** (`core.json`): разбор и запись, без сторонних библиотек.
2. **Клиент модели** (`core.llm`) на `HttpClient` с `SSLContext` из
   настроек:
   - OpenAI-совместимый: `POST …/v1/chat/completions`, `stream: true`,
     `Authorization: Bearer`; конец потока — `[DONE]` или закрытие
     соединения;
   - Anthropic Messages: `POST …/v1/messages`, `x-api-key`,
     `anthropic-version: 2023-06-01`, события `content_block_delta`,
     `message_stop`, `error`;
   - адрес: `https://host`, `https://host/v1` и полный адрес метода
     работают одинаково;
   - пустой токен допустим (локальные Ollama, LM Studio) — заголовок
     авторизации тогда не шлётся;
   - если сервер не стал стримить и вернул обычный JSON — берём ответ из
     него;
   - отмена запроса; таймауты: подключение, начало ответа, простой
     потока (сервер замолчал посреди ответа).
3. **Понятные ошибки** по-русски: хост не найден, соединение отклонено,
   таймауты, сертификату нет доверия (с подсказкой добавить CA), сертификат
   выдан на другое имя или просрочен, http на https-порт, HTTP 400/401/403/
   404/429/5xx с текстом ошибки сервера. Токена нет ни в одном сообщении.
4. **Диалог** (`ChatSession`): ответ растёт по мере стриминга, «Стоп»
   оставляет полученную часть с пометкой «остановлено», «Повторить» после
   ошибки или остановки. Эхо-провайдер — только для тестов.
5. **Вид чата:**
   - текст ответа появляется постепенно (перерисовка не чаще ~25 раз в
     секунду), прокрутка не дёргает, если пользователь читает выше;
   - «Отправить» на время ответа становится «Стоп», Esc в поле ввода —
     тоже стоп;
   - ошибка — своим цветом, со ссылкой «Повторить»;
   - модель не настроена — вместо пустой ленты подсказка и ссылка
     «Открыть настройки»;
   - строка состояния: модель, сервер, что происходит;
   - цвета из темы (читается и в тёмной теме EDT).
   Отправка остаётся по Ctrl+Enter, как принято в Eclipse.
6. **Настройки:**
   - «Макс. токенов ответа» (пусто — по умолчанию: для Anthropic 8192, в
     OpenAI-совместимый не передаётся);
   - кнопка «Проверить подключение»: короткий настоящий запрос с текущими
     значениями полей, результат на странице;
   - предупреждение, если токен уйдёт по `http://` не на localhost.
7. **Тесты:**
   - `core`: JSON, разбор SSE (в том числе событие, разрезанное между
     пакетами), оба протокола против фейкового сервера, ответ без
     стриминга, отмена, таймаут простоя, ошибки HTTP и сети, HTTPS с
     тестовым CA (доверяем / не доверяем / чужое имя), токен не попадает
     в тексты ошибок, нормализация адреса, новые настройки;
   - UI: вид без настроек показывает подсказку; с настройками на фейковый
     сервер — ответ стримится в ленту, «Стоп» останавливает, ошибка
     показывается с «Повторить»; скриншоты этих состояний.

Критерии готовности:

- `./mvnw -B verify` зелёный локально и в CI на обеих ОС, скриншоты в
  артефактах;
- в EDT на Windows чат отвечает реальной моделью по OpenAI-совместимому
  протоколу (например, локальная Ollama или LM Studio) и по Anthropic;
- в КСПД на Astra чат отвечает внутренней моделью по https с корпоративным
  CA из PEM-файла.

### Этап 3. UI/UX ленты чата (текущий)

Ответы модели читаются как документ, код из ответа берётся одним щелчком,
диалог не теряется при перезапуске.

Состав:

1. **Markdown** (`core.markdown`): разбор подмножества в «текст + стили»,
   UI только применяет стили к `StyledText`.
   - Блоки: заголовки `#`, абзацы с сохранением переводов строк, списки
     (`-`, `*`, `1.`, вложенные, `[ ]`/`[x]`), цитаты `>`, разделитель
     `---`, таблицы (моноширинно, колонки выровнены), блоки кода ``` и ~~~
     с языком.
   - Внутри строки: `**жирный**`, `*курсив*`, `_курсив_` (только на
     границе слова — `имя_переменной` не трогаем), `~~зачёркнутый~~`,
     `` `код` ``, `[текст](url)`, `<url>` и голые `http(s)://…`, экранирование
     `\*`.
   - Незакрытый блок кода во время стриминга показывается как код до конца
     текста.
2. **Блоки кода:** шрифт редактора (`JFaceResources.TEXT_FONT`), фон на всю
   ширину ленты, над кодом строка с языком и ссылками «Копировать» и
   «Вставить в редактор». Вставка заменяет выделение в активном текстовом
   редакторе (в том числе модуль BSL) и отменяется через Ctrl+Z; если
   редактора нет или он только для чтения — сообщение в строке состояния.
3. **Ссылки** открываются во внешнем браузере через браузер Eclipse
   (`IWorkbenchBrowserSupport`), только `http`, `https`, `mailto`.
4. **Действия у сообщений** в строке заголовка:
   - ответ: «Копировать» (исходный Markdown), у последнего — «Повторить»;
   - своё сообщение: «Изменить» — текст возвращается в поле ввода, это
     сообщение и всё после него убираются;
   - ошибка: «Повторить».
   Контекстное меню ленты: «Копировать», «Выделить всё», «Новый чат».
5. **Поле ввода:** Enter — отправить, Shift+Enter — новая строка, Ctrl+Enter
   — тоже отправить. Поле растёт по тексту от 2 до 10 строк. ↑ / ↓ в пустом
   поле — предыдущие отправленные сообщения.
6. **«Новый чат»** на панели вида вместо «Очистить историю». Текущий диалог
   сохраняется в `<рабочая область>/.metadata/.plugins/io.github.hansglorias.edtai.ui/chat.json`
   и восстанавливается при открытии вида; оборванный ответ восстанавливается
   как «остановлено».
7. **Системный промпт** в настройках: многострочное поле, по умолчанию —
   короткий промпт про 1С:Предприятие и EDT. Пустое поле — без системного
   промпта. OpenAI-совместимый — сообщение `system`, Anthropic — поле
   `system`.
8. **Тесты:**
   - `core`: Markdown (каждая конструкция, вложенность, незакрытые
     разметка и блок кода, таблицы, `_` внутри слов, ссылки), слияние стилей
     в непересекающиеся отрезки, кодек и файл истории, `editFrom`, повтор
     готового ответа, системный промпт в обоих протоколах, хранение промпта;
   - UI: ответ с Markdown — стили на месте (жирный, код моноширинным, фон
     блока кода), «Копировать» кладёт код в буфер, «Вставить в редактор»
     меняет текст в открытом редакторе и отменяется, «Изменить», Enter /
     Shift+Enter, ↑ в пустом поле, восстановление диалога после повторного
     открытия вида, «Новый чат»; скриншоты, в том числе узкий вид.

Критерии готовности:

- `./mvnw -B verify` зелёный локально и в CI на обеих ОС, скриншоты в
  артефактах;
- в EDT на Windows и на Astra ответ с кодом BSL читается: код
  моноширинный на фоне, «Вставить в редактор» вставляет в модуль, Ctrl+Z
  отменяет; диалог переживает перезапуск EDT.

### Этап 4. Контекст EDT

- «Спросить AI о выделенном» в контекстном меню редактора и по горячей
  клавише.
- Над полем ввода — прикреплённый контекст (модуль, строки, объект
  метаданных по пути), его можно снять.
- «Вставить в редактор» заменяет выделение, отменяется через undo.

### Этап 5. Инструменты

- Вызов инструментов в обоих протоколах, включая стриминг `tool_calls` /
  `tool_use`; цикл агента с лимитом шагов.
- Подтверждение вызова панелью над полем ввода: «Разрешить / Разрешать в
  этом чате / Отклонить».
- Сначала встроенные инструменты только на чтение (прочитать модуль, поиск
  по проекту, список объектов), потом запись с показом изменений через
  `org.eclipse.compare`.

### Этап 6. MCP

- Клиент MCP: JSON-RPC по stdio и Streamable HTTP, `initialize`,
  `tools/list`, `tools/call`; инструменты серверов — в общем реестре с
  встроенными.
- Состояние серверов на странице настроек.
- Astra: домашний каталог с `noexec`, поэтому команду stdio-сервера задаём
  через интерпретатор (`python3 server.py`) — описать в инструкции.
