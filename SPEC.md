# EDT AI — задание

## Что это и зачем

Плагин для 1C:EDT, который добавляет в IDE чат с языковой моделью и (в
следующих этапах) даёт модели инструменты через MCP. Целевое использование —
в том числе закрытый контур (КСПД): модель доступна по внутреннему адресу,
TLS через корпоративный CA, интернета нет.

Репозиторий публичный: адреса, токены, имена хостов и сертификаты из КСПД
сюда не попадают ни в код, ни в тесты, ни в README.

## Целевые окружения

| Окружение | EDT | Eclipse | ОС / UI |
|---|---|---|---|
| Рабочая машина | 2026.1, 2025.2 | 4.30 (2023-12) | Windows 10/11, win32 |
| КСПД | 2025.x | 4.30 (2023-12) | Astra Linux, GTK 3 |

Обе версии EDT собраны на Eclipse 4.30, Java 17. Если в КСПД окажется EDT на
другом Eclipse, target platform опускается до него.

## Архитектурные решения

- **Только Eclipse 4.30.** Target platform — релиз 2023-12, собираем
  против него. API новее 4.30 не используем. Нижние границы версий в
  `Require-Bundle` ставим не выше 4.30.
- **Java 17.** `Bundle-RequiredExecutionEnvironment: JavaSE-17`.
- **Без SWT Browser.** На Astra нет гарантированного WebKitGTK, на Windows
  Edge/IE ведут себя по-разному. Весь UI — обычный SWT/JFace.
- **Сертификаты.** Поддерживаем корпоративный CA: системное хранилище ОС
  (на Windows `Windows-ROOT`) плюс дополнительный PEM-файл. Отключить
  проверку сертификатов нельзя.
- **Токен — только в Eclipse Secure Storage.** В обычных preferences и
  логах токена нет.
- **Ядро без UI.** `core` не зависит от SWT/JFace и тестируется headless.
- **Без внешних библиотек** на первом этапе: только то, что есть в
  платформе 4.30. Каждая новая зависимость должна ставиться в закрытом
  контуре из того же zip.

## Этапы

### Этап 1. Каркас (текущий)

Плагин без реального функционала, но со всем, что нужно, чтобы дальше
наращивать: интерфейс, настройки, тесты, CI, установка.

Состав:

1. **Вид «AI Chat»** (категория «AI»): история сообщений, многострочное
   поле ввода, кнопка «Отправить» (и Ctrl+Enter), «Очистить», переход к
   настройкам. Вместо модели — эхо-провайдер, отвечает асинхронно, UI не
   блокируется.
2. **Страница настроек** «EDT AI» в Window → Preferences:
   - протокол (OpenAI-совместимый / Anthropic Messages);
   - адрес сервера, модель;
   - токен — в Secure Storage;
   - сертификаты: системное хранилище ОС, дополнительный PEM-файл с
     проверкой, что он читается;
   - список MCP-серверов: имя, транспорт (stdio / http), команда или URL,
     вкл/выкл; добавить, изменить, удалить.
3. **Тесты:**
   - `core`: сериализация настроек и MCP-списка, валидация, хранение
     токена в Secure Storage, загрузка PEM, сборка `SSLContext`,
     эхо-провайдер, история чата;
   - UI smoke-тест в живом workbench: открыть вид, отправить сообщение,
     дождаться эха, открыть страницу настроек.
4. **CI** на Ubuntu и Windows (`mvn -B verify`). На Ubuntu UI-тесты под
   xvfb с GTK — ближе к Astra в CI не получится.
5. **Zip update-site** в артефактах CI.
6. **README**: сборка, установка в EDT из zip, установка в закрытом контуре.

Критерии готовности:

- `mvn -B verify` зелёный локально и в CI на обеих ОС;
- zip update-site лежит в артефактах CI;
- плагин ставится в EDT 2025.2 и 2026.1 через Help → Install New
  Software → Archive, вид открывается, эхо отвечает, настройки
  сохраняются и переживают перезапуск, токен не виден в
  `.metadata/.plugins/org.eclipse.core.runtime/.settings`;
- то же на Astra Linux в КСПД.

### Этап 2. Подключение к модели

HTTP-клиент (`java.net.http`) с `SSLContext` из настроек, OpenAI-совместимый
и Anthropic протоколы, стриминг, отмена запроса, понятные ошибки сети и TLS.

### Этап 3. Контекст EDT

Передача модели выделенного кода, текущего модуля, объекта метаданных.

### Этап 4. MCP

Запуск MCP-серверов из списка настроек (stdio / http), выдача их
инструментов модели, подтверждение вызовов пользователем.
