## Текущая задача: диагностика BSL

Ветка `codex/edt-module-diagnostics`: после `edit_module` модель получает
ограниченный снимок native диагностики EDT. `check_module` повторяет чтение
без записи. MCP не обязателен. Контракт, исследованные API, ограничения
и ручной чек-лист — [EDT_MODULE_DIAGNOSTICS.md](EDT_MODULE_DIAGNOSTICS.md).

Ключевой предел: полученный снимок не доказывает завершения проверки новой
редакции. Пустой список не означает отсутствие ошибок. Статусы недоступности,
несохранённого текста, смены редакции и таймаута сохранять явно.
Пользователь выбрал сначала реализацию и автотесты; проверит адаптер в EDT
сам. Не создавать тестовые проекты и не менять его рабочий код без запроса.

Необязательный UI adapter использует OSGi service `IMarkerManager` через
reflection, provider classloader и workspace path файла (не EMF URI).
В target нет EDT API, новых библиотек или зависимости от MCP.
Один ограниченный native read; зависший вызов удерживает слот до возврата,
новые вызовы не создают очередь потоков. Сбой диагностики не отменяет правку.

LANG=C.UTF-8; UI с отдельным user.home. Полный Windows+Ubuntu verify — CI.

из успешного main CI нужного SHA. Не повторять зелёные проверки без причины.
