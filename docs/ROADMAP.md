# План развития EDT AI

Составлен 30.10.2026 по пожеланиям к чату, моделям, токенам, маркерам и оркестрации.

## Уже есть в проекте

1. Любое имя модели задаётся в настройках. Поэтому Qwen не требует отдельной интеграции.
2. Кнопка списка моделей загружает доступные модели через `/v1/models`. В КСПД нужно проверить фактический адрес и формат ответа сервера.
3. В строке состояния уже показываются токены последнего ответа: вход, выход и занятое окно. Если сервер не прислал usage, показывается оценка.
4. При вызовах инструментов уже видны текущая фаза, имя операции и длительность.
5. Ошибки переполнения окна, сети, TLS и отказа инструментов уже распознаются отдельно.
6. Для инструментов уже есть защита от повторного вызова с теми же аргументами.

## Сделано сейчас

1. В списке чатов показывается состояние живого диалога: «отвечает…» или «готово».
2. Состояние обновляется при начале и завершении ответа, в том числе когда ответ идёт в другой вкладке.
3. После отправки сообщения история сохраняется сразу, поэтому чат поднимается в начало списка именно после отправки.
4. Сборка без UI тестов проходит.

## Ближайшие небольшие задачи

### 1. Режимы диалога — сделано (#48)

Добавить четыре готовых режима в меню чата и рядом с кнопкой отправки:

1. Вопрос и ответ.
2. Варианты решения.
3. Рекомендация с обоснованием.
4. План реализации.

Режим не меняет модель и не требует нового формата истории. Он добавляет к вопросу короткую инструкцию. Выбранный режим должен быть виден в строке состояния и сбрасываться после отправки. Логику держать в `core`, а выбор режима сделать в UI. Покрыть форматирование инструкции тестами `SlashCommandTest` или отдельным тестом.

### 2. Токены по операциям — сделано (#49)

Сейчас доступны общие токены ответа. Следующий небольшой шаг:

1. Для каждого шага цикла агента сохранить входные и выходные токены.
2. Показать их в строке вызова операции и в раскрываемой информации ответа.
3. Для оценённых значений явно оставить знак приблизительности.
4. В конце ответа показывать сумму, как сейчас.

Изменение требует расширить `ToolUse` или добавить отдельную запись статистики шага. Выбор зависит от того, нужна ли статистика только в текущей ленте или ещё и после перезапуска. Сначала использовать `ToolUse`, чтобы не менять формат истории без необходимости.

### 3. Ошибки вызова инструментов

Улучшить уже существующий путь ошибок:

1. Разделять неверный JSON аргументов, отсутствие инструмента, отказ пользователя, ошибку самого инструмента, таймаут и отказ сервера от tool calling.
2. Показывать краткую причину в строке операции.
3. В подсказке или раскрытии показывать технический текст без токена и секретов.
4. Не отключать все инструменты из за ошибки одного MCP инструмента.
5. Добавить core тесты на каждый класс ошибки.

Основа уже есть в `AgentLoop`, `ModelErrors` и `ToolUse`, поэтому это отдельная, но понятная задача размера S или M.

### 4. Проверка Qwen в КСПД

Код для Qwen не добавлять. Провести ручную проверку конфигурацией:

1. Получить фактический URL совместимого API.
2. Загрузить список моделей.
3. Проверить обычный ответ.
4. Проверить потоковый ответ.
5. Проверить Qwen с рассуждением и варианты полей `reasoning_content` или `<think>`.
6. Проверить вызов встроенного инструмента и MCP.

По результату добавить только совместимость, которая реально нужна конкретному шлюзу.

## Отдельные большие задачи

### 5. Оркестрация моделей

Разделить настройки на универсальную лёгкую модель и мощную модель:

1. Отдельное подключение и токен для каждой роли, либо безопасная ссылка на общее подключение.
2. Выбор маршрута по типу задачи: обычный вопрос, код, план, ревью, инструменты, сжатие истории.
3. Явный ручной выбор модели в сообщении.
4. Резервная модель при недоступности основной.
5. Отдельный учёт токенов и ошибок по каждой модели.
6. Проверка, что история и токены не смешиваются между ролями.

Это не делать вместе с простыми режимами диалога. Нужны изменения `AiSettings`, `SettingsStore`, `ModelChatProvider`, UI настроек и тестов.

### 6. Маркеры EDT и визуализация ревью

Разделить на два этапа:

1. Маркеры EDT: создавать Eclipse markers с файлом, строкой, серьёзностью и текстом находки.
2. Клик по маркеру открывает редактор на нужной строке.
3. Для каждого ответа хранить связь находки с сообщением и чатом.
4. Ревью кода должно возвращать структурированный формат, а не только текст Markdown.
5. В ленте оставить обычный текстовый запасной вариант, если модель вернула невалидный JSON.
6. Добавить команды удалить маркеры этого ревью и удалить все маркеры EDT AI.

Это отдельная большая задача размера L. Нельзя надёжно строить маркеры только разбором произвольного текста модели. Сначала нужно согласовать формат находки и жизненный цикл маркеров.

## Предлагаемый порядок PR

1. Завершить текущую ветку параллельных чатов.
2. Режимы диалога.
3. Токены по операциям.
4. Диагностика ошибок инструментов.
5. Проверка Qwen и точечная совместимость.
6. Маркеры EDT и структурированное ревью.
7. Оркестрация моделей.

Оркестрацию и маркеры не объединять с небольшими UI изменениями.
