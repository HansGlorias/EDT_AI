# Выполнение инструментов и контекст модели

Первый архитектурный этап для небольших локальных моделей (31.10.2026).

## Разделение ответственности

- `AgentLoop` управляет запросами, разрешениями, выполнением и отменой.
- `ToolExecutionLedger` хранит факты выполнения в пределах одного ответа.
  Он не зависит от протокола и не удаляет записи при обрезке контекста.
- `AgentTranscript` хранит полные шаги и строит их представление для
  OpenAI-совместимого или Anthropic-протокола. Сокращение представления
  не меняет журнал и исходные результаты.
- `RequestBudget` по-прежнему выбирает, какие результаты и старые сообщения
  передать. Строгая гарантия попадания запроса в окно — следующий этап.

Так будущие страницы результатов, отбор инструментов и бюджет смогут
менять контекст, не разрешая повторное выполнение уже сделанной операции.

## Контракт инструментов

`Tool.repeatableRead()` означает, что повторное выполнение не имеет
побочных эффектов. По умолчанию `false`: `modifies() == false` недостаточно,
поскольку сохранение навыка, создание вложения и публикация ревью тоже
имеют эффекты. Признак разрешения пользователя также не описывает эффект.

Чтения ProjectTools, git status/diff/log и skill объявляют этот контракт
явно. Для MCP требуется `readOnlyHint == true`; имя get/list само по себе
не доказывает безопасность. Обёртка ToolActivity сохраняет контракт.
Ложная аннотация стороннего сервера остаётся ограничением доверия серверу.

## Решения журнала

Ключ вызова — имя и канонический JSON аргументов: порядок полей любого
вложенного объекта неважен, порядок массивов и текст строк сохраняются.
Числа нормализуются. Разные имена/пути одного объекта пока не объединяются.

| Предыдущее состояние | Что делает цикл |
|---|---|
| Вызова не было | Выполняет после нужного разрешения |
| Пользователь отклонил | Возвращает отказ, не спрашивает повторно |
| Успешная операция с возможным эффектом | Возвращает сохранённый результат с пометкой о повторе, без выполнения и дублирования вложений |
| Ошибка операции с возможным эффектом | Не выполняет повторно: результат неопределённый, сначала нужна проверка состояния |
| Успешное чтение, результат ещё виден | Отклоняет бесполезный повтор |
| Успешное чтение, результат исключён из запроса | Разрешает новое чтение |
| После предыдущего чтения начата операция с возможным эффектом | Разрешает новое чтение, даже если операция завершилась ошибкой |
| Чтение завершилось SERVER/TIMEOUT | Разрешает одну повторную попытку; повторный сбой блокируется |
| Другая ошибка чтения | Возвращает ошибку без повторного выполнения |

Начало операции с возможным эффектом увеличивает поколение данных всего
ответа. Это консервативная инвалидация чтений, а не версия файла: изменение
пользователем или другим чатом пока автоматически не обнаруживается.
Сохранённый результат операции не является проверкой текущего состояния.

Состояния STARTED, SUCCEEDED, FAILED, DENIED описывают факт попытки.
STARTED/FAILED для операции с возможным эффектом не доказывает ни успех,
ни отсутствие изменения. Текст ошибки сохраняется для диагностики.

## Отмена и протокол

Цикл проверяет отмену перед очередным запросом, между вызовами одного
пакета, после ожидания разрешения и перед запуском инструмента. Уже
начавшийся вызов может завершиться, особенно если сервер не поддерживает
отмену; его эффекты автоматически не откатываются. Это не транзакция.

Сокращённые результаты сохраняют признак ошибки и связь с вызовом в обоих
протоколах. Аргументы старых вызовов пока остаются в контексте. Обрезка
контекста не меняет таблицу решений журнала для операций с эффектами.

## Границы первого этапа

Журнал живёт только в одном AgentLoop. Новый вопрос, «Повторить» и перезапуск
создают новый журнал: сквозная идемпотентность пока не обеспечивается.
Внутренние повторы McpClient/McpTool не менялись. Чтение изменившегося
асинхронного статуса и проверка версии документа потребуют отдельных
контрактов. Новых запросов к модели сам журнал не добавляет.

Следующие отдельные этапы:

1. Единый снимок цели запроса и версии источников; явное обновление чтений.
2. Строгий общий бюджет, ограниченные результаты и их дочитывание.
3. Сохранение подтверждённых действий между ответами и корректное сжатие.
4. Профили инструментов и проверка изменённого BSL средствами доступного EDT.

Независимые задачи: строгие аргументы встроенных инструментов, сохранение
structuredContent MCP и воспроизводимый набор задач для реальной модели.
Телеметрию всех запросов вводить отдельно: счётчики журнала нельзя выдавать
за полную стоимость задачи (сжатие, название и повторы транспорта отдельно).

## Проверка

AgentExecutionTest проверяет фактические вызовы и следующий запрос fake
model server: чтение после эффекта, восстановление и предел повторов
временной ошибки, неопределённый результат записи, повтор записи после
обрезки, сохранность вложений, отказ с переставленными полями JSON,
остановку между вызовами. Чтение после эффекта и обрезка записи проверены
в обоих протоколах. AgentTranscriptTest проверяет целостность пар и
сохранение ошибки при сокращении представления.

Эти тесты доказывают поведение Java-кода. Улучшение успешности, токенов и
скорости Qwen 7–14B требует отдельного измерения на реальном сервере.
