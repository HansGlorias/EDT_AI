Код уже в `main` через PR #98–101; последний SHA на момент сверки — `81ff881`. Полный CI Windows и Ubuntu для него прошёл. Исходная передача ниже сохранена; сведения о непройденных проверках относятся к моменту её написания. Контракты описаны в
[SPEC.md](../SPEC.md) (разделы про специалистов, уточнения, план, окно модели).

## Что сделано

1. **Время и токены ответа** (`core.chat.ReplyStats`, сохраняется в истории
   полем `stats`). Под ответом — время конца (раньше показывалось время
   начала, совпадавшее с вопросом), длительность, «думала N», токены;
   подсказка с разбивкой; «подробнее» — карточка с полосами фаз (ожидание,
   рассуждение, текст, инструменты), токенами, специалистами, долгими
   вызовами. У строк вызовов дольше секунды — их время.
2. **Панель специалистов** (`ui.SubagentsPanel`, `core.chat.Subagents`).
   `ExploreProject` пишет запись `ToolUse.SUBAGENT` на запуск (роль: задача,
   отчёт до 4000 знаков, токены); модель её в следе не видит.
3. **Форма уточнений** (`ui.UserQuestionsBar`): карточки с полосой
   состояния, «отвечено N из M», Ctrl+Enter.
4. **План файлом** (`core.chat.PlanFile`, панель плана в `ChatView`):
   `plans/<id чата>.md` в папке состояния, открывается в текстовом
   редакторе EDT; исправленный план уходит модели как утверждённая редакция
   (`PlanApproval.execute`). Новая зависимость UI: `org.eclipse.core.filesystem`.
5. **Работа на Qwen 27B** — по выгрузкам реальных чатов:
   - зацикливание на повторах: предупреждение, затем ответ без инструментов
     (`AgentLoop.STUCK/FINAL`);
   - разведчик на лимите шагов даёт итог запросом без инструментов;
   - след вызовов для модели без токенов и шагов специалистов, следы
     посреди ответа вычищаются (`ChatMessage.stripTraces`);
   - рабочая часть окна для шагов: ½ бюджета, 32k–80k токенов
     (`RequestBudget.working`), убирание старых результатов пачкой ради
     кэша префикса сервера; страница результата до 20 000 символов при
     большом окне (`RequestBudget.page`);
   - `edit_module` без учёта пробельных различий (табы/пробелы, номера строк
     из read_module), отступы — в стиле модуля (`tools.LooseMatch`);
   - проверка заявленных правок: «добавил/внёс/что сделал» без успешного
     инструмента изменения — одна пометка модели (`AgentLoop.UNMADE_CHANGES`,
     `llm.ChangeClaims`);
   - правило в `TOOL_RULES`: макет формы встроенными инструментами не правится.
6. **Выгрузка для анализа**: `reply_stats` у ответа, `duration_ms` у вызова,
   время ответов и число REPEATED в сводке, `diff` у правки по полным текстам
   (`core.chat.LineDiff`).

## Что сделать дальше

1. Релиз UI/Qwen уже завершён (#98–101). Следующий этап — [диагностика модуля](EDT_MODULE_DIAGNOSTICS.md); сигнал завершения проверки новой редакции пока не подтверждён.
2. Ручная проверка в EDT (Windows, Astra):
   - время/«подробнее» под ответом, подсказка; старые чаты открываются;
   - панель специалистов при `delegate_task`/`explore_project`, «скрыть»;
   - форма уточнений, Ctrl+Enter, радиокнопки на Windows;
   - режим «План»: «Открыть план в редакторе», правка, Ctrl+S, утверждение —
     модель выполняет исправленный текст;
   - правка модуля, где модель пишет отступы пробелами.
3. Бэклог по выгрузкам Qwen 27B (по приоритету):
   - **ошибки EDT после правки**: вернуть модели ошибки модуля из валидации
     EDT после `edit_module` (опечатки вида `Предупждение`, выдуманные методы).
     Сначала выяснить на живом EDT, как он отдаёт ошибки BSL (маркеры
     ресурсов Eclipse или свой механизм);
   - **настройка «без специалистов»** или их отключение для слабых моделей:
     на Qwen 27B два запуска съели ~70% токенов ответа и вернули partial;
   - **оглавление модуля** (процедуры/функции с номерами строк, есть
     `context.BslMethods`) и правило «независимые чтения — одним шагом»:
     Sonnet делает 6 шагов там, где Qwen ~22;
   - **инструмент макета форм** или EDT-MCP: MCP у пользователя не подключён,
     задачи «добавь кнопку» решаются только наполовину;
   - калибровка символов на токен по usage сервера (3 символа/токен
     занижает на коде).

Выгрузки пользователя содержат код рабочего проекта — в репозиторий их не
класть, в тестах только синтетика.
