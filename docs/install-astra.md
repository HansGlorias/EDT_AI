# Установка в EDT на Astra Linux без прав администратора

Как поставить EDT AI в 1C:EDT на машине, где EDT установлена от root и `sudo`
у пользователя нет. Ниже: пошаговая установка, почему не работает обычный путь
через Install New Software и что может исправить администратор, чтобы плагины
EDT ставились штатно.

Проверено на Astra Linux 1.8, 1C:EDT 2024.2.6 (Eclipse 4.30, Java 17),
EDT в `/opt/1C/1CE/components/1c-edt-2024.2.6+7-x86_64`.

## Коротко

- Install New Software в такой EDT не ставит **никакой** плагин, не только
  наш. Плагин тут ни при чём.
- Обходной путь — [`tools/edtai-user-install.sh`](../tools/edtai-user-install.sh).
  Он подключает плагин без p2 и ничего не пишет в каталог EDT.
- EDT с плагином нужно запускать через `bash ~/.edt-ai/edt.sh`.

## Установка

### 1. Перенести файлы на машину

Нужны два файла:

- zip update-site: артефакт `edtai-update-site` из GitHub Actions или
  `releng/io.github.hansglorias.edtai.repository/target/*.zip` из сборки;
- скрипт [`tools/edtai-user-install.sh`](../tools/edtai-user-install.sh).

Дальше считаем, что они лежат в `/tmp/edtai.zip` и
`~/edtai-user-install.sh`. Положить zip:

```bash
cp ~/Downloads/edtai-update-site.zip /tmp/edtai.zip
```

Если скрипт не скачать, его можно создать в терминале: `cat > ~/edtai-user-install.sh <<'EOF'`,
затем вставить содержимое файла и строку `EOF`.

### 2. Закрыть EDT и запустить скрипт

```bash
bash ~/edtai-user-install.sh /tmp/edtai.zip /opt/1C/1CE/components/1c-edt-2024.2.6+7-x86_64
```

Второй параметр — каталог EDT. Если его не указать, скрипт возьмёт самую
новую EDT из `/opt/1C/1CE/components`.

Скрипт запускается через `bash …`, а не `./…`: запуск файлов из
домашнего каталога может быть запрещён (`noexec`), и тогда будет «Отказано в
доступе».

Скрипт должен вывести «Готово» и два jar: `io.github.hansglorias.edtai.core_…`
и `io.github.hansglorias.edtai.ui_…`.

### 3. Запустить EDT с плагином

```bash
bash ~/.edt-ai/edt.sh
```

Выбрать прежнюю рабочую область: настройки EDT, раскладка и проекты хранятся
в ней, поэтому всё будет как раньше. Вид — Window → Show View → Other → EDT AI →
EDT AI или значок «EDT AI» в строке состояния внизу окна.

### Обновление, удаление, ограничения

- **Новая версия плагина или обновление EDT.** Повторить шаг 2 с новым zip.
  Скрипт копирует список компонентов EDT на момент запуска; после обновления
  EDT старый список не подойдёт.
- **Удаление:**
  ```bash
  rm -rf ~/.edt-ai
  ```
- **Только через `~/.edt-ai/edt.sh`.** Ярлык из меню и 1C:EDT Start
  запускают EDT без плагина.
- **Installation Details.** Плагин не виден в Installed Software, потому что
  p2 о нём не знает. Он есть на вкладке Plug-ins.

### Что делает скрипт

1. Достаёт jar плагина из zip в `~/.edt-ai/plugins`.
2. Копирует системный список бандлов EDT
   (`<EDT>/configuration/org.eclipse.equinox.simpleconfigurator/bundles.info`)
   в `~/.edt-ai/bundles.info` и дописывает в конец наши jar.
3. Создаёт `~/.edt-ai/edt.sh`. Этот скрипт запускает EDT:
   - с `-Dorg.eclipse.equinox.simpleconfigurator.configUrl=file:~/.edt-ai/bundles.info`:
     EDT грузит бандлы по нашему списку, а не по системному. Значения из
     `config.ini` не перекрывают свойства, уже заданные через `-D`, поэтому
     подмена работает. Свойство передаётся через `_JAVA_OPTIONS`, потому что
     `-vmargs` в командной строке заменил бы все `-vmargs` из `1cedt.ini`;
   - с `-configuration ~/.edt-ai/configuration`: конфигурация в каталоге,
     куда пользователь точно может писать;
   - с `-Djava.io.tmpdir=~/.edt-ai/tmp`: временный каталог, который точно
     существует (см. причину 2 ниже).

p2 при этом не участвует, поэтому ошибки из следующего раздела не возникают.

## Почему не работает Install New Software

Причин было три. Первые две — особенности конкретной машины, третья
ломает установку любых плагинов.

### 1. EDT в каталоге root — режим shared install

EDT стоит в `/opt/1C/1CE/components/…`, владелец root, писать туда
пользователь не может. Eclipse в таком случае работает в режиме **shared
install**: базовая установка только читается, а всё, что ставит
пользователь, p2 кладёт в его пользовательскую область
`<user.home>/.eclipse/org.eclipse.platform_4.30.0_<хеш>_linux_gtk_x86_64/`.
Там же лежит профиль p2 пользователя.

На Windows EDT обычно стоит в профиле пользователя и доступна на запись,
поэтому там Install New Software работает.

### 2. Пользовательская область указывает на несмонтированный диск

При запуске из меню EDT вычисляла пользовательскую область как
`/mnt/<пользователь>-personal-disk/.eclipse/…`. Это пустой каталог root на
системном диске: точка монтирования, в которую личный диск не смонтирован.
Ошибка в `.metadata/.log`:

```
Невозможно выполнить запись в репозиторий: file:/mnt/<пользователь>-personal-disk/.eclipse/org.eclipse.platform_4.30.0_…
java.io.IOException: Не удалось создать каталог /mnt/<пользователь>-personal-disk/.eclipse/…/plugins.
```

В интерфейсе это выглядит как «Произошла ошибка при сборе элементов для
установки».

С этим связана переменная окружения `_JAVA_OPTIONS`, которую выставляют
скрипты входа в систему. В ней `java.io.tmpdir` задан **дважды**, двумя
разными путями:

```
-Djava.io.tmpdir=/mnt/<пользователь>-personal-disk/tmp -Djava.io.tmpdir=/mnt/<пользователь>-<номер>-personal-disk/tmp
```

Первый путь устаревший, на несмонтированный диск. Смонтирован второй: на нём
лежит рабочая область EDT. Где именно EDT берёт первый путь для
пользовательской области, мы до конца не выяснили. Из терминала, где `HOME`
указывает на `/home/<пользователь>`, область была в `~/.eclipse`. Скорее
всего, окружение графического сеанса или ярлыка отличается от терминального.

Обход — запуск с `-configuration` в каталоге, доступном на запись.

### 3. p2 падает на компоненте 1C:Link — ломает установку любого плагина

После обхода второй причины установка дошла до следующего шага и упала уже
на нём («Произошла ошибка при установке элементов»):

```
контекст сеанса: (профиль=DefaultProfile, этап=…phases.Install,
  операнд=null --> [R]com.company1c.link.agent.publicator.linux 4.0.2,
  действие=…touchpoint.eclipse.actions.ChmodAction).
Действие chmod не удалось, файл /opt/1C/1CE/components/1c-edt-2024.2.6+7-x86_64/plugins/com.company1c.link.agent.publicator.linux_4.0.2/binaries/nginx/nginx не существует.
```

Когда пользователь ставит что-то в shared install, p2 строит его профиль
поверх базового и выполняет шаги установки для компонентов, которых в этом
профиле ещё нет. Среди них компонент 1C:Link
`com.company1c.link.agent.publicator.linux`. Один из его шагов —
`chmod` на встроенный `nginx`, а файла `nginx` в установленной EDT нет.
Шаг падает, p2 откатывает всю операцию. Наш плагин в ней только «попутчик»,
так же упадёт установка любого другого.

Там же при каждом запуске 1C:Link пишет
`Astra Linux 1.8 x86-64 (1.8_x86-64) - не поддерживаемая операционная система`.
Похоже, на этой ОС 1C:Link установлен не полностью, поэтому `nginx`
и отсутствует.

### Прочие наблюдения

- **Домашний каталог смонтирован с `noexec`.** Поэтому `./script.sh` даёт
  «Отказано в доступе», а в логе EDT есть
  `Не удалось загрузить библиотеку: libunixfile_1_0_0.so … сбой отображения сегмента`:
  Eclipse распаковывает нативную библиотеку в конфигурацию в домашнем
  каталоге и не может её загрузить. Это не критично: EDT переходит на
  `java.io.File` и работает чуть медленнее с файлами.
- **p2 director без root** (`1cedt -application org.eclipse.equinox.p2.director …`)
  падает с «Неизвестный параметр -nl». В `1cedt.ini` `-nl` передаётся без
  значения, а director такое не принимает. Нужно явно указать язык:
  `-nl ru_RU`.

## Что может сделать администратор

Варианты в порядке предпочтения. В КСПД из них пока не проверен ни один.
Наш обходной путь проверен.

### Поставить плагин централизованно, от root

Плагин станет виден всем пользователям при обычном запуске, без скриптов.
EDT должна быть закрыта:

```bash
sudo /opt/1C/1CE/components/1c-edt-2024.2.6+7-x86_64/1cedt -nosplash -nl ru_RU -consoleLog -application org.eclipse.equinox.p2.director -repository 'jar:file:/tmp/edtai.zip!/' -installIU io.github.hansglorias.edtai.feature.feature.group
```

Удаление — та же команда с `-uninstallIU` вместо `-installIU`.

Так установка идёт в базовый профиль, где 1C:Link уже установлен, поэтому
проблема с `nginx` возникнуть не должна. Если всё же возникнет, сначала
нужно исправить 1C:Link (следующий пункт).

### Починить или убрать 1C:Link

Это главное, что мешает ставить любые плагины из-под пользователя:

- если 1C:Link нужен — переустановить компонент EDT так, чтобы
  `plugins/com.company1c.link.agent.publicator.linux_*/binaries/nginx/nginx`
  был на месте. Возможно, его удалила политика безопасности или установщик
  пропустил его на «неподдерживаемой» Astra 1.8;
- если 1C:Link не используется — удалить его из EDT (от root через
  Installation Details или p2 director с `-uninstallIU`).

После этого Install New Software из-под пользователя должен работать: плагины
будут ставиться в его пользовательскую область.

### Привести в порядок `_JAVA_OPTIONS` и личный диск

- Убрать из `_JAVA_OPTIONS` устаревший `-Djava.io.tmpdir=/mnt/<пользователь>-personal-disk/tmp`
  и оставить один путь — на реально смонтированный диск.
- Убедиться, что к моменту входа пользователя личный диск смонтирован и все
  пути, которые используют EDT и Java, существуют и доступны на запись.

Найти, где задаётся переменная:

```bash
grep -rn "personal-disk" /etc/profile /etc/profile.d /etc/environment /etc/xdg 2>/dev/null
```

### Другие варианты

- **Выдать группе разработчиков право на запись в каталог EDT.** Тогда
  Install New Software будет ставить в базовую установку, как на Windows.
  Проще всего, но пользователи смогут менять EDT для всех.
- **Положить jar плагина в `<EDT>/dropins/` от root.** Обычно работает в
  Eclipse, но установку из `dropins` тоже выполняет p2. В КСПД не проверено.

## Диагностика

Где смотреть, если установка снова сломается:

- **Error Log в EDT:** Window → Show View → Other → Error Log. У записи
  об ошибке установки разверните вложенные записи (треугольник): причина
  там, а не в верхней строке.
- **Файл лога рабочей области:** `<рабочая-область>/.metadata/.log`.
  Логи, изменённые за последний час:
  ```bash
  find ~ /mnt -path '*/.metadata/.log' -mmin -60 2>/dev/null
  ```
- **Запуск с выводом лога в терминал:**
  ```bash
  /opt/1C/1CE/components/1c-edt-2024.2.6+7-x86_64/1cedt -consoleLog
  ```
- **Версия Eclipse в EDT:**
  ```bash
  ls /opt/1C/1CE/components/1c-edt-*/plugins | grep -E '^org\.eclipse\.(platform|ui)_'
  ```
