# Выгрузка выбранного чата для разбора

В меню вида EDT AI: «Выгрузка этого чата для разбора (ZIP)…».
В контекстном меню строки истории: «Выгрузка для разбора (ZIP)…» —
сохраняется именно выбранная строка, текущий чат не переключается.
Обычный экспорт Markdown остаётся отдельным действием.

Перед выбором файла открывается форма. По умолчанию содержимое выключено:
есть только состояния, счётчики и текущие настройки модели. Новый экспорт
всегда начинает с этого значения. Отдельный флажок включает разговор,
прикреплённый текст/код, краткие итоги инструментов, доступные снимки правок
и введённый отзыв «Ожидал / Получил / Что не так». Поля отзыва необязательны;
без содержимого в архиве остаётся шаблон для последующего заполнения.
Экспорт — только локальный ZIP; автоматической отправки человеку или ИИ нет.

Содержимое может быть конфиденциальным. Известный текущий токен, URL,
известные адреса подключений и поля авторизации очищаются перед сериализацией,
включая сообщения, ошибки, код, имена, настройки и отзыв. Secure Storage,
preferences, HTTP-заголовки и глобальные журналы не копируются в архив.
Чтение токена из Secure Storage необходимо только для очистки и может
потребовать штатную разблокировку; ошибка чтения отменяет экспорт.
Сам токен не хранится в экспортируемой модели данных и не логируется.

Это **не полная анонимизация**: неизвестные/старые ключи, произвольные
идентификаторы, пути, персональные данные или секреты в необычном формате
могут остаться в явно включённом тексте. Перед передачей проверьте все файлы
ZIP вручную. Отзыв, добавленный после распаковки, также надо проверить.

## Файлы ZIP, schema_version = 1

| Файл | Данные |
|---|---|
| `manifest.json` | Версия схемы/плагина, случайный ID архива, время, явный content_included, текущий профиль и полнота |
| `conversation.md` | Сообщения в порядке истории, состояния, краткие шаги; при явном включении — доступный текст и контекст |
| `conversation.json` | Структурированные сообщения, ToolUse, provenance usage, снимки правок; поля отсутствующих данных |
| `summary.md` | Размер выборки, состояния/ошибки, известные подытоги usage по источникам и список пробелов |
| `feedback.md` | Отзыв пользователя или незаполненный шаблон |

Все файлы UTF-8, фиксированные имена, без произвольных путей ZIP.
Архив сначала записывается во временный файл рядом с выбранным, затем
заменяет назначение (атомарно, если файловая система поддерживает).
Подготовка и запись идут в фоне; остальные чаты не читаются.
Снимок отвечающего чата помечен `active_snapshot=true`: он может быть неполным.

`configuration.scope=export_time_configuration_not_historical`: экспорт
не знает параметры каждого прошлого ответа. Модель берётся с учётом
действующей привязки выбранного чата; режим/лимиты — текущие, для занятого
чата режим зафиксирован при начале ответа. Endpoint, CA-пути, системный
промпт, серверы MCP и секреты не являются полями профиля. Окно 0 означает
автоматический выбор/предположение, max output 0 — настройку по умолчанию,
а не измеренные нулевые лимиты сервера.

Текстовые поля имеют `status` (`available`, `withheld`, `unavailable`,
`truncated`) и `value` (строка либо null). `available` — доступный текст
после очистки, не гарантия отсутствия изменений/секретов.
`withheld` — выключено пользователем; `unavailable` — источник этого
не сохраняет. `truncated` — сработал предел выгрузки. Имена инструментов
и модель — метаданные, они остаются и без текста разговора, с очисткой.

Пределы: 1000 сообщений, 5000 ToolUse, 1000 доступных записей правок,
до 100 контекстов/вложений на сообщение, 20 000 UTF-16 символов на поле,
2 000 000 символов содержимого/метаданных всего. Исходные и экспортированные
количества/обрезка показаны отдельно. Двоичные вложения не выгружаются.
Весь репозиторий, текущие файлы и git HEAD не сканируются.

## Что действительно известно

- История выбранного чата: роли, время, статус текста; при включении —
  сохранённые сообщения, контекст и текстовые вложения, включая карточки ревью.
- ToolUse: имя, статус, класс проблемы, краткие summary/outcome, позиция
  в тексте ответа. Это отображаемые записи, включая служебные notices,
  а не доказательство фактического исполнения каждого вызова.
- Usage, прикреплённый к первому инструменту шага, если он сохранён.
  Input/output/context раздельно содержат `value` и `provenance`:
  `SERVER`, `ESTIMATE`, `UNKNOWN`, `MIXED`. UNKNOWN имеет null, известный
  серверный ноль остаётся 0. Старое поле estimated читается существующим кодеком.
- После #90 progress-записи explore_project различаются по известному
  структурированному формату ID `parent/child/UUID/...`, а не тексту summary.
  Они отмечены `execution_scope=exploration_child`, usage имеет отдельный scope;
  локальные child-N/parent_tool_id связывают их внутри архива, исходные ID
  не выгружаются. Источник классификации указан явно. Для остальных старых
  записей parent/child scope неизвестен (`parent_or_unspecified`), он не угадывается.
- Последний usage живого чата, если есть, отмечен
  `scope=last_reply_aggregate`, `includes_child_usage=true`. Это родительская
  сумма последнего ответа, она **не прибавляется** к дочерним шагам.
- Правки встроенного edit_module: только уже привязанные к сообщениям
  снимки before/after, живущие в памяти этого вида. Наблюдённые изменения
  ресурсов MCP содержат путь; before/after unavailable. Причина/авторство
  такого изменения не доказаны одним наблюдением. Перезапуск теряет снимки.

Сводка суммирует только раздельные SERVER/ESTIMATE известных записей шагов
родителя и разведчика (каждую запись один раз, без cumulative aggregate),
показывает их покрытие; MIXED не разбивается догадкой и не прибавляется
к этим суммам. Context не суммируется. Число записей usage или ToolUse
не выдаётся за число физических запросов. FAILED включает отказ/дубль,
не только ошибку реального исполнения; progress дочернего чтения не равен
новому решению ведущей модели. Нулевое число доступных снимков
не означает, что правок не было.

## Пробелы полного trace и следующий этап

`completeness.overall=incomplete` во всех архивах этой версии.
Текст ответа модели не используется для реконструкции инструментальных фактов.

| Сейчас отсутствует | Что потребуется собирать по opt-in |
|---|---|
| Связь выбранного чата с выполнением | chat-local task/run IDs, parent run, request/span/parent span, жизненный цикл начала/завершения/отмены |
| Все физические запросы | События begin/end для answer/title/summary/retry, ошибочные/отклонённые попытки, request ID и причина повтора |
| Точное время | Start/first byte/first visible/end, длительности; ожидание человека отдельно, без сложения пересечений |
| Аргументы и полные результаты tool | Logical call → approval/denial/duplicate → execution → result/effect; ограниченные очищенные payload и ссылки на страницы/снимки, с явной обрезкой |
| Транспорт MCP | Каждая initialize/list/call попытка, reconnect, retry и связь с logical call; blocked duplicate не исполнение |
| Полная стоимость | Usage по каждому request, источник каждой половины, cache/reasoning semantics, wire bytes и состав контекста; parent и child не суммировать дважды |
| Устойчивые изменения | Версии источников и ограниченные before/after/diff, привязанные к сообщению/run; неизвестный эффект записи отдельно |

У каждого сообщения/ToolUse есть `links` с nullable `task_id`, `run_id`,
`parent_run_id`, `request_id`, `span_id`, `parent_span_id`. Сейчас они null:
исполнительных ID история не сохраняет. `message-N`/`tool-N` — ссылки только
внутри этой выгрузки (`id_scope=export_local_not_execution_trace`), а не
восстановленные ID запросов. Будущие версии могут заполнять связи только
из реально собранных событий, с явной версией схемы и источником данных.

Нынешний [DiagnosticLog](LOCAL_DIAGNOSTICS.md) анонимный и не имеет связи
с выбранным чатом: включать весь журнал или приписывать его числа этому
чату нельзя. Подключение request diagnostics, подробный bounded trace,
настройки opt-in/retention и реестр корреляции — отдельные изменения.
Этот экспорт не зависит от незавершённой интеграции диагностики.

## Проверки

Core: состав/схема ZIP, выключенное и включённое содержимое, известные
секреты/URL/авторизация, кириллица, UNKNOWN/MIXED/серверный ноль, отсутствие
двойного счёта parent, неполные данные, обрезка, изоляция выбранного чата,
отсутствие глобальной диагностики и двоичных вложений, замена архива.
UI: меню выбранного/текущего чата, default off и сброс выбора, отзыв,
отмена двух диалогов, отказ очистки, локальная запись; снимки формы.
Полный регресс Windows/Ubuntu — в CI до merge.

## Историческая модель ответа и имя ZIP

Новые сообщения ответа и ошибки сохраняют `ReplyModel(protocol, model)`
из подключения, зафиксированного ModelChatProvider перед первым запросом
ответа. Смена настроек во время или после ответа не меняет эту запись.
Запись переживает сохранение истории и обновление потокового ответа.
В conversation.json это `reply_model` со scope `response_connection_snapshot`;
значения доступны и при выгрузке без текста. Это настроенный model id
запроса, не доказательство фактического веса модели за серверным alias.
Детские/служебные запросы отдельно по моделям пока не трассируются.
У прежних ответов статус `unknown`: восстановить модель задним числом нельзя.
`manifest.configuration` по-прежнему описывает текущие настройки с явным
scope `export_time_configuration_not_historical`, историческую запись не заменяет.

Имя файла по умолчанию — `<название выбранного чата>-analysis.zip`.
Недопустимые символы Windows, управляющие символы, конечные точки/пробелы,
зарезервированные имена и чрезмерная длина обработаны без потери кириллицы.
Пользователь может изменить имя и отменить сохранение обычным FileDialog.
