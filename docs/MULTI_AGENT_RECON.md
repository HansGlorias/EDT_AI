## Что уже работает

Ведущая модель вызывает `explore_project(question, scope?)` для широкого
поиска и связей нескольких модулей. Дочерний AgentLoop имеет отдельный
контекст и зафиксированное подключение родителя. История родителя и его
полный набор инструментов ребёнку не передаются.

Первая версия выполняет одного ребёнка за раз, на глубине 1, только с
исходными чтениями ProjectTools. MCP, git, правки, рекурсивные запуски и
вопросы пользователю ребёнку недоступны. Есть программные лимиты запусков,
физических запросов и размера отчёта. Родитель ждёт future без опроса
модели; Stop отменяет дочернюю цепочку, поздний ответ её не возобновляет.
Вопросы и утверждение плана остаются у ведущего через механизм #89.

Родителю возвращается один ограниченный отчёт с явным статусом и областью
успешных чтений. Подробный дочерний transcript и его snapshot ID наружу не
передаются. Статус complete не доказывает истинность выводов или полноту
поиска: перед правкой ведущий перечитывает код. Общего EvidenceStore,
проверки версий всех источников и сохранённых полных трасс здесь нет.

Дочерний usage учитывается в сумме ответа без повторного сложения
накопительных обновлений. Context остаётся свойством запроса ведущего;
прерванный запрос без usage оставляет полный расход неизвестным. Это не
полная диагностика всех физических запросов: её отдельно ведёт root.

## Следующая практическая проверка

Пройти реальные задачи на выбранной модели: связи нескольких модулей,
поиск вызовов функции, объяснение большого метода, влияние правки на
подписки, отмена и перечитывание перед записью. Проверить partial/ошибки,
ссылки, пропуски, время и расход с раздельным происхождением токенов.
Методика — [DEVELOPER_SCENARIOS.md](DEVELOPER_SCENARIOS.md), общий показ —
[DEMO_RUNBOOK.md](DEMO_RUNBOOK.md).

При необходимости сравнивать прямое адресное чтение с разведчиком на
одинаковых задачах. Это проверка полезности уже работающей функции и
способ выбрать дальнейшие улучшения. Предварительного A/B допуска к
разработке нет; прежние числовые пороги экономии не являются обязательством.
Автотесты механики не подтверждают качество Qwen и выигрыш на любой модели.

## Независимый бэклог

- Ограниченная группа независимых исследований с общим ожиданием и частичными
  результатами. Не вводить заранее постоянный опрос через spawn/status/poll.
- Фоновые исследования с уведомлением о завершении, понятным владением
  задачей и общей отменой. Параллельность и диспетчер задач пока не реализованы.
- Версии источников и общий ограниченный реестр доказательств: срок жизни,
  доступ по задаче, устаревшие чтения и противоречивые отчёты. Нынешние
  поколения ledger не являются версиями файлов.
- Общие квоты группы по запросам, памяти, времени и конкуренции на endpoint.
  Существующие защитные пределы ребёнка не означают общий бюджет всей задачи.
- Подробная корреляция parent/child и осознанно включаемая запись выбранного
  чата по [CHAT_ANALYTICS_EXPORT.md](CHAT_ANALYTICS_EXPORT.md). Не подменять
  metadata-only [DiagnosticLog](LOCAL_DIAGNOSTICS.md) записью кода и промптов;
  прошлую трассу нельзя восстановить задним числом.
- Читающий MCP и разные подключения/модели для ролей: отдельные контракты
  разрешений, доверия, секретов и учёта. AUTO родителя не расширяет права
  ребёнка; scope не становится песочницей только из-за названия параметра.

Это направления отдельных небольших PR, а не обязательный объём одного
изменения или очередь предварительных условий. Каждое расширение сохраняет
запрет дочерних правок, изоляцию контекста и защиту от позднего продолжения.
Локально — затронутые проверки; в CI — полный Windows/Ubuntu verify.
