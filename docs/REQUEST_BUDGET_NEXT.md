# Следующий PR: бюджет подготовленного запроса

Зависимость: PreparedRequest фиксирует именно отправляемое тело и раздельно
даёт размер JSON, UTF-8 байты и оценку входа. Этот документ — контракт
следующего изменения; описанное ограничение ещё не реализовано.

## Правила

- Проверять финальный подготовленный запрос после сокращения истории и
  результатов инструментов. Оценка учитывает системные инструкции, схемы,
  историю, вложения и пары вызов/результат.
- Явный max_tokens резервировать целиком. Если он не оставляет места входу,
  возвращать понятную ошибку настройки до HTTP, не выделять искусственно
  четверть окна поверх заданного резерва.
- Для Anthropic брать резерв из реально отправляемого max_tokens. Текущее
  расхождение 8192 в теле и до 4096 в бюджете устранить. Изменение значения
  по умолчанию, если понадобится для малого окна, согласовать в том же PR
  с текстом настроек и тестами, а не молча обрезать пользовательское значение.
- При отсутствующем max_tokens у OpenAI-совместимого сервера резерв является
  предположением плагина. Не выдавать его за ограничение сервера и не менять
  совместимость добавлением параметра без отдельного решения.
- Если минимальный запрос всё ещё превышает оценочный бюджет, завершать
  подготовку объяснением причины до отправки. Не удалять последний вопрос
  или его код без уведомления; не выполнять инструменты при такой ошибке.
- При отказе сервера по размеру окна ограниченные повторы могут уменьшать
  контекст. Новый снимок создаётся для каждой попытки; журнал операций и
  сохранённые результаты не сбрасываются, записи не повторяются.
- Символьная эвристика и стоимость изображений остаются оценками. Успех
  локальной проверки бюджета не гарантирует принятие серверным токенизатором.

## Проверка

Fake-server сценарии для обоих протоколов и окон 8/16/32k: явный и
автоматический выход; схемы занимают большую часть входа; огромный результат
MCP; большой последний вопрос; изображения; отказ сервера после успешной
локальной оценки. Проверять фактически переданное тело, отсутствие HTTP при
непомещающемся минимуме, целостность call/result и отсутствие повторных записей.

Отдельно на реальной небольшой модели измерить долю принятых запросов,
успешность задач и расход за задачу. Эти результаты нельзя получить из
fake-server тестов. Метрики названия и сжатия подключаются отдельным PR
диагностики; текущий счётчик ответа не называть полной стоимостью задачи.
