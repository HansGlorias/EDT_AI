# Демо EDT AI: Qwen или MiniMax

Основной показ 15 минут, короткий 10, расширенный 20, включая рассказ.
Подготовлено для утра 03.11.2026 по `main` после #79 (`5c77ba5`).
**Репетиции ещё не проведены; качество и скорость на выбранной модели
не подтверждены.** Это показ, не сравнительный benchmark.
Базовый показ использует одну модель. Телеметрию и steering в рамках
подготовки не реализуем; оркестрация не нужна для сценария.

## До показа: заполнить локально

| Условие | Фактическое значение |
|---|---|
| EDT AI: установленный commit / источник update-site | не заполнено |
| Модель Qwen либо MiniMax: точный ID / revision / размер / quantization | не определено; неизвестное оставить unknown |
| Сервер: название / версия / tool parser / chat template | не заполнено |
| Окно: клиент / сервер; max output; reasoning | не заполнено |
| ОС / EDT / Java / платформа; оборудование | не заполнено |
| Demo workspace / demo project / архив исходного проекта | не заполнено |
| EDT-MCP: версия / доступность get_edt_version | не проверено |

Предположение владельца — окно 100–128k, возможно меньше. Это не измеренное
значение: вписать реальные лимиты клиента и сервера. Размер и способ
развёртывания модели неизвестны; не называть любую Qwen/MiniMax небольшой
локальной моделью. Успех при 128k не доказывает работу на 7–14B с окном
8–32k: для такого вывода нужен отдельный прогон конкретной конфигурации.

Полные настройки — в локальной копии
[configuration-template.json](scenarios/configuration-template.json).
Не угадывать окно по имени модели. До репетиции подтвердить у сервера
совместимый протокол и tool calling. В EDT AI включить встроенные инструменты,
режим **Агент**, авторежим выключить, MCP отключить. Начать новый пустой чат;
системный промпт взять из шаблона, max output 2048, лимит кода 40000 символов,
названия чатов включены. Навыки отключить и зафиксировать этот профиль.
Все эти параметры одинаковы в трёх репетициях. Секреты/внутренние адреса,
сырые ответы и журналы в репозиторий и на публичный экран не переносить.

## Подготовка безопасной копии (вне времени показа)

Источник — существующие [карточки и oracle](../tests/io.github.hansglorias.edtai.core.tests/fixtures/developer-scenarios/scenarios.json)
и [методика](DEVELOPER_SCENARIOS.md). Нового набора задач нет.
Все команды выполняются из корня EDT AI, Python 3.10+ (`python3` на Astra,
если так называется интерпретатор). В кавычках заменить пути на абсолютные.

1. Создать **отдельный demo workspace**, без рабочего проекта владельца.
   Фикстуры содержат только шесть `Module.bsl`: нет `.project`, `.mdo`,
   готовой базы или импортируемого EDT-проекта. Команда ниже создаёт
   лишь staging с исходниками и отказывается перезаписывать каталог:

   ```text
   python tools/developer_scenarios.py prepare "<новый staging вне workspace>"
   ```

2. В мастере установленной EDT создать пустую конфигурацию `Сценарии1С`
   без БСП. Создать общие модули РасчетыЗаказов, ОформлениеЗаказов,
   ПодсказкиЗаказов, БуферЗаказов, ЗапросыТоваров, ПроверкаЗаказов.
   Свойства по методике: Сервер=Да, Вызов сервера=Да, Глобальный=Нет,
   привилегированный режим и повторное использование выключены,
   остальные клиентские/внешние контексты выключены. Вставить текст
   соответствующего `staging/src/CommonModules/<имя>/Module.bsl` целиком,
   без добавления строк. Сохранить; метаданные оставить созданными EDT.
   Нужная версия платформы должна быть установлена заранее.
   Допустима копия уже существующего безопасного demo project, если эти
   модули и их строки совпадают с фикстурами; рабочий проект не использовать.
3. Дождаться сборки, записать исходные ошибки EDT. Проверить, что нет
   несохранённых буферов. В **корне одноразового demo project** создать
   локальную базу git; корень должен быть самостоятельным, не внутри
   рабочего git-репозитория. Сначала проверить путь в терминале/проводнике:

   ```text
   git -C "<demo project>" init
   git -C "<demo project>" config core.autocrlf false
   git -C "<demo project>" add .
   git -C "<demo project>" commit -m "demo baseline"
   git -C "<demo project>" status --short
   ```

   Ожидается пустой status. При ошибке любой команды остановиться.
   Не добавлять remote. После закрытия EDT сохранить отдельную неизменяемую
   копию исходного **реального EDT-проекта вместе с .git и метаданными**.
   Она понадобится для сброса. Не путать её с staging из шага 1.
4. Перед S02/S05 открыть только demo workspace, закрыть редакторы, убрать
   вложения, выбрать demo project. Снимок сохранять вне project, после сборки:

   ```text
   python tools/developer_scenarios.py snapshot "<demo project>" "<новый каталог артефактов>/before-main.json"
   ```

`check` ожидает ровно шесть BSL исходного набора и контролирует остальные
файлы целиком. Если существующий EDT-проект содержит дополнительные BSL,
проверка исходного снимка не пройдёт. Не удалять метаданные/модули ради
зелёного oracle и не объявлять её успешной: подготовить проект по методике
или явно записать ограничение и проверить весь diff вручную. Изменения
служебных файлов EDT тоже требуют разбора. Файловая проверка не заменяет
проверку трассы, редактора и ошибок EDT.

иначе вопросы и разбор границ. Подготовка/сброс проекта выполняются до

Точные промпты берутся из карточек, не переписываются перед неудачным повтором:

```text
python tools/developer_scenarios.py show S02
python tools/developer_scenarios.py show S05
```

S02 — отправить ровно:

> Найди реализацию расчёта суммы заказа со скидкой, которую использует ОбщийМодуль.ОформлениеЗаказов. Дай модуль, функцию и строки; кратко объясни формулу. Код не меняй.

Ожидаемые факты: РасчетыЗаказов.СуммаСоСкидкой, строки 8–10;
вызов ОформлениеЗаказов.СуммаЗаказа на строке 8; одноимённая функция
ПодсказкиЗаказов — другая. Проверить действительное чтение исходников,
а не только уверенный текст. Перед переходом убедиться, что файловых правок нет:

```text
python tools/developer_scenarios.py check S02 "<demo project>" "<каталог артефактов>/before-main.json"
git -C "<demo project>" diff --exit-code
git -C "<demo project>" status --short
```

S05 — новый чат без вложений; отправить ровно:

> В ОбщийМодуль.РасчетыЗаказов только в СуммаСоСкидкой измени округление с двух знаков на целое число. Больше ничего не меняй. Прочитай результат после правки.

В ленте проверить чтение **после** записи и новый текст; предварительное
чтение не подходит. Показать «Изменения» в EDT AI, затем независимо от
слов модели — git diff/EGit в этом же проекте:

```text
git -C "<demo project>" diff -- src/CommonModules/РасчетыЗаказов/Module.bsl
git -C "<demo project>" diff --stat
git -C "<demo project>" status --short
python tools/developer_scenarios.py check S05 "<demo project>" "<каталог артефактов>/before-main.json"
```

Успех: в одной строке только точность округления `2 → 0`; весь целевой
модуль совпадает с [эталоном S05](../tests/io.github.hansglorias.edtai.core.tests/fixtures/developer-scenarios/expected/S05.bsl),
остальные файлы неизменны. Дождаться EDT; новых ошибок от правки быть
не должно. Если буфер остался dirty, сначала выяснить причину; не объявлять
сохранённый diff проверкой несохранённого текста. Не просить модель
коммитить, запускать shell или «исправить всё».

S03 — **дополнение до 20 минут**, если его заранее отрепетировали.
`python tools/developer_scenarios.py show S03`:
скопировать `prompts[0]` без изменений. Oracle: настоящие вызовы в
ОформлениеЗаказов, строки 8 и 18; строка, комментарий, локальный вызов
и определение ПодсказкиЗаказов не являются вызовами целевой функции.
Это поиск текста с проверкой чтением, не доказательство семантического
поиска ссылок. На отдельной чистой копии заранее сделать новый snapshot:

```text
python tools/developer_scenarios.py snapshot "<demo S03 project>" "<новый каталог артефактов>/before-S03.json"
python tools/developer_scenarios.py check S03 "<demo S03 project>" "<каталог артефактов>/before-S03.json"
git -C "<demo S03 project>" diff --exit-code
git -C "<demo S03 project>" status --short
```

Первая команда до промпта, остальные после ответа. Не использовать для S03
проект с уже выполненной правкой S05.

Готовить заранее в **другой исходной disposable copy**, не поверх S05.

инструментами исключена), MCP выключен. Отправить `prompts[0]` S11 дословно.

ПроверкаЗаказов: ноль ошибочно разрешён. Исходник должен остаться с `>=`.

```text
python tools/developer_scenarios.py check S11 "<demo review project>" "<каталог артефактов>/before-review.json"
```

Если модель не работает — показать **заранее сохранённый реальный** результат
репетиции с датой/конфигурацией и назвать его записью. Если такой записи
нет — показать исходник/diff и объяснить oracle, не имитировать успех модели.

## MCP — отдельная необязательная проверка S12

Основной показ не зависит от MCP. В настройках проверить реально установленный
EDT-MCP и фактический список инструментов. S12 требует именно `get_edt_version`:
если его нет, отметить S12 `not_run`/`blocked_environment`, не подставлять
выдуманное имя или заглушку. Зелёный индикатор [MCP](MCP_STATUS.md)
подтверждает связь, а не правильность работы модели/доступность операции.

Оценщик заранее делает отдельный контрольный вызов этого инструмента
доступным клиентом MCP и сохраняет результат; он вне интервала задачи
и не передаётся модели. На отдельной чистой копии перед промптом:

```text
python tools/developer_scenarios.py snapshot "<demo MCP project>" "<новый каталог артефактов>/before-S12.json"
```

В EDT AI разрешить только этот MCP-инструмент,
авторежим выключен, новый чат. `python tools/developer_scenarios.py show S12`:
отправить точный `prompts[0]`, разрешить фактический вызов. Сверить версию
с контролем; после ответа проверить файлы:

```text
python tools/developer_scenarios.py check S12 "<demo MCP project>" "<каталог артефактов>/before-S12.json"
git -C "<demo MCP project>" diff --exit-code
git -C "<demo MCP project>" status --short
```

На сцену отвести до двух минут в расширенном плане; иначе пропустить.

## Сброс и три репетиции

Сброс — закрыть EDT без сохранения результатов и восстановить baseline
в **новый отсутствующий каталог**, а не reset/clean рабочего проекта:

```text
python -c "import shutil; shutil.copytree('<исходная копия EDT demo project>', '<новый demo project для следующего прогона>')"
```

Оба пути заранее проверить: источник — сохранённая baseline-копия из шага 3,
назначение — новый disposable каталог. `copytree` откажется перезаписывать
существующий. Открыть восстановленный проект через штатный импорт существующего
EDT-проекта в **новом demo workspace**; не открывать две копии с одним именем
в одной рабочей области. Формат импорта зависит от установленной EDT:
проверить на репетиции. Если копирование проекта не поддерживается этой
версией, снова пройти мастер и вставить те же модули; staging импортом не
становится. Новый чат, прежние настройки, новый каталог артефактов/снимок.

Ниже **пустой журнал**, не результаты. Выполнить владельцу три раза
S02 → S05 с независимой проверкой; S11 проверить отдельно хотя бы один раз.
Сбой не затирать успешным перезапуском. Фиксировать каждый ID отдельно;
S02 и S05 в свежих чатах, поэтому это не тест памяти длинного диалога.

| 1 | не заполнено | not_run | не измерено | unknown |
| 2 | не заполнено | not_run | не измерено | unknown |
| 3 | не заполнено | not_run | не измерено | unknown |

Статусы: pass/partial/fail/timeout/blocked_environment/not_run по методике.
Если модель не завершила ответ за 2 минуты, на показе остановить, назвать
сцену незавершённой и перейти к запасному варианту; оставшееся время сцены —
на проверку/переход. Это demo cutoff, **не** методический timeout
600 секунд. Сохранить затраченное время и причину, не записывать pass.
Если есть любые побочные правки — остановиться и показать diff, не скрывать.

из доступных свидетельств; input/output provenance независимо `server`,

отсутствие не равно 0; не складывать серверные числа с оценками.
Строка состояния не доказывает полную стоимость задачи, cache/reasoning
не прибавлять повторно. Подробности и локальная сводка —
[методика](DEVELOPER_SCENARIOS.md) / [RESULTS](scenarios/RESULTS.md).
Три репетиции для готовности показа не заменяют матрицу 15 задач × окна ×
5 повторов и не доказывают статистическую значимость.

## Рассказ на две минуты

- **0:00–0:30 — задача.** «Хотим разбирать и править 1С прямо в EDT
  с доступной нам моделью. Показываем поиск реализации,
  ограниченную правку и проверку результата на известных исходниках».
- **0:30–1:10 — реализовано.** «Есть инструменты поиска/чтения/правки,
  diff и ревью с маркерами; журнал выполнения отделён от сокращаемого
  контекста, большие результаты можно дочитывать. После #79 подготовленный
  запрос проверяется по **оценке** бюджета до HTTP; это не точный tokenizer
  и не гарантия принятия сервером» ([границы бюджета](REQUEST_BUDGET_NEXT.md)).
- **1:10–1:40 — границы доказательств.** «Автотесты с fake model проверяют
  механизмы, не качество Qwen или MiniMax. На этой модели подтверждены только фактически
  показанные/записанные прогоны; пока репетиций нет, таких результатов нет.
  Проценты экономии и полную стоимость не заявляем. Локальный диагностический
  writer ещё не подключён к рабочим запросам» ([статус](LOCAL_DIAGNOSTICS.md)).
- **1:40–2:00 — дальше.** «Сначала закрепляем модель и условия, собираем
  реальные успешные и неудачные прогоны с происхождением usage. Затем
  сравниваем изменения контекста и набора инструментов. Телеметрия,
  steering и оркестрация — отдельные последующие решения. Маршрутизация
  между Qwen Max/Flash — идея для обсуждения, не реализованная функция».
