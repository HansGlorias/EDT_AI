# Агенты, инструменты и знания: направление развития

Решения и гипотезы на 04.11.2026. Пользователь выбрал ближайший фокус:
мультиагентность и экономное использование всех разрешённых инструментов.
Это карта небольших PR, а не обязательная последовательность большого релиза.
Состояние реализации сверять с [WORKSTREAMS.md](WORKSTREAMS.md) и контрактами.

## Принципы

- Ведущий удерживает задачу пользователя, принятые решения и ответственность
  за итог. Подзадача получает явную цель, область, критерии результата;
  история родителя целиком не копируется.
- Отдельный агент оправдан самостоятельным результатом: исследование связей,
  ревью diff, проверка результата. Простой read/search не требует делегирования.
- Полный разрешённый каталог MCP доступен для поиска. Схемы загружаются по
  необходимости и ограничиваются бюджетом запроса, а не постоянным числом
  «нужных» инструментов. Режим чата, фильтр владельца и разрешения сохраняются.
- Роль определяет задачу и возможности, а не только имя в промпте. Читающий
  специалист не получает запись; ведущий сохраняет доступные операции записи.
- Отчёт модели не становится доказательством: факты вызовов, ошибки и результаты
  проверок учитываются отдельно. Проверка синтаксиса не доказывает бизнес-логику.
- Изоляция уменьшает объём основного контекста, но не гарантирует меньший
  суммарный расход. Считать запросы всех участников, включая служебные.
- Работа без интернета и с единственной локальной моделью остаётся полноценным
  вариантом. Java 17, Eclipse 4.30, Windows/Astra; новых библиотек не требуется.

## Ближайшее развитие мультиагентности

Практический приоритет после обратной связи Qwen 27B — дать ведущему и
проверяющему факты диагностики BSL: [контракт](EDT_MODULE_DIAGNOSTICS.md).
`check_module` возвращает ограниченный снимок, не утверждение об успешной
проверке. Это общий инструмент, а не повод запускать ещё одного специалиста
для каждой правки. Настройка отключения специалистов, оглавление модулей,
проверка макетов форм и калибровка оценки токенов остаются в бэклоге.

1. **Исследователь, ревьюер, проверяющий.** Общий жизненный цикл ребёнка,
   ограниченный отчёт, общий счётчик запусков в ответе, отмена и учёт usage.
   Ревьюер читает фактический diff и код, проверяющий — доступную диагностику
   EDT-MCP. Читающий MCP подключается тем же каталогом схем по запросу.
   Первая версия выполняет детей последовательно на модели родителя.
2. **Уточнение результата существующего ребёнка.** Сохранить ограниченный
   контекст подзадачи до завершения ответа, дать ведущему задать дополнительный
   вопрос без повторного изучения всех модулей. Лимиты не сбрасываются.
   Явно определить освобождение памяти, Stop и актуальность источников.
3. **Общий бюджет задачи и планировщик выполнения.** Ограничить физические
   запросы всей группы, время, объём результатов и конкуренцию на endpoint.
   При достижении предела вернуть частичный результат; не превращать символьную
   оценку токенов в точный серверный usage.
4. **Независимые параллельные подзадачи.** Сначала чтение и ревью. Готовность
   приходит событием/future; модель не опрашивает детей платными запросами.
   Параллельность настраивается: один GPU может не ускориться от двух запросов.
5. **Планировщик и исполнитель.** Отдельный планировщик нужен для самостоятельного
   анализа большой задачи. Дочерняя запись — отдельный этап: область владения,
   версии исходников, конфликт правок, проверка применения и откат. Пока пишет
   ведущий. Несколько исполнителей без контроля пересечений не запускаем.
6. **Независимая оценка готовности.** Проверять конкретные критерии и результаты
   инструментов; не вводить обязательный совет агентов или голосование. Модель
   той же семьи может повторить ошибку исполнителя.

## Инструменты без постоянного урезания каталога

- Убрать фиксированный предел выбранных схем; сохранить атомарное отклонение
  выбора, который не помещается в бюджет, и предыдущий рабочий набор.
- Обновлять tools/list в той же MCP-сессии после серверного включения toolset.
  Не заменять это проверкой в новом соединении: видимость может быть сессионной.
  Стабильные имена, фильтр/режим и запрет вызова ещё не объявленной схемы обязательны.
- Добавить поиск по категориям и русским/английским терминам без скрытого
  исключения остальных инструментов. При неудачном поиске доступен полный каталог.
- Подробные руководства получать по запросу (например, get_tool_guide EDT-MCP).
  Отдельный консультант по сложным инструментам возможен позднее, но не нужен
  перед каждым вызовом. Сгенерированное описание не заменяет схему сервера.

## Сохранённые независимые направления

| Направление | Следующий предметный шаг | Что пока не доказано |
|---|---|---|
| Профили генерации | Необязательные temperature/top-p/top-k, thinking и effort с таблицей возможностей server/protocol/model; default не отправляет поле | Оптимальные значения для используемого Qwen, фактическая поддержка шлюзом |
| Preserve thinking | Разделить продолжение инструментального цикла, прошлые ходы и показ текста; политика по контракту сервера | Универсальная полезность сохранения/удаления рассуждений |
| Разные модели по ролям | Ссылка роли на профиль подключения, секрет только Secure Storage; расход по ролям | Выигрыш Flash/Max относительно одной модели |
| Скиллы | Переработать существующие инструкции: область, шаги, проверки, типовые ошибки, версии и источники; references по запросу | Переносимость чужого скилла на BSL и небольшую модель |
| Промпты | Заимствовать конкретные приёмы из открытых источников и связывать с наблюдаемыми сбоями; не копировать весь продуктовый промпт | Что инструкция, полезная Claude, улучшит Qwen |
| База знаний / RAG | Локальные документы с источниками, версиями и адресным дочитыванием; затем гибридный поиск по словам и embeddings через необязательный локальный сервис/MCP | Что векторный поиск даст пользу сверх структуры EDT, точного поиска и документации |
| Память и доказательства | Версии прочитанных источников, подтверждённые операции между ответами, обнаружение устаревших отчётов | Полнота восстановленной истории без подробной трассы |
| Аналитика | Связать task/run/child и служебные запросы; параметры генерации и результаты проверок; содержимое только по явному включению | Точные затраты запроса без server usage |
| Уточнение во время работы | Принять новое поручение на безопасной границе цикла; определить отмену и изменения цели | Возможность повлиять на уже выполняемую сервером генерацию без её остановки |

RAG здесь означает получение релевантных фрагментов перед ответом, не обучение
модели. Векторный индекс — необязательное средство поиска по смыслу. Для имён
методов, связей и точных ссылок сначала используем структуру и поиск EDT.
Устаревший документ исключается по версии; найденный код перечитывается перед
правкой. Закрытые материалы и частные правила команды не публикуются в плагине.

## Как принимать небольшие изменения

Автотесты Java проверяют контракт: список схем, ограничения прав, атомарность,
отмену, изоляцию, лимиты, корректный учёт и экспорт. Полный Windows/Ubuntu CI
обязателен перед merge, локально — только затронутые сценарии.

Практическая проверка использует [DEVELOPER_SCENARIOS.md](DEVELOPER_SCENARIOS.md):
объяснение подсистемы; ревью известного diff; небольшая правка с диагностикой;
ошибка инструмента/Stop; большой каталог при небольшом окне. Сохранять модель,
сервер, настройки, исходный SHA, критерии правильности, длительность всей задачи,
серверный usage отдельно от оценок, запросы детей/родителя и повторы.
Не складывать накопительный child usage повторно и не считать progress-записи
дополнительными фактическими вызовами. Ускорение со слов пользователя — полезное
наблюдение, а не воспроизводимый замер.
