# Обработка проведения документа

1. Прочитай модуль объекта документа (`read_module`, «Документ.Имя.Модуль
   объекта») и регистры, по которым он делает движения (`list_objects`,
   `get_metadata_details` через MCP, если есть). Если в проекте принята
   схема с модулем менеджера (`ИнициализироватьДанныеДокумента`) —
   следуй ей.
2. Каркас:
   ```bsl
   Процедура ОбработкаПроведения(Отказ, РежимПроведения)
       // Записываем движения целиком: без чтения старых.
       Движения.ОстаткиТоваров.Записывать = Истина;
       // 1. Данные — одним пакетным запросом (временные таблицы).
       // 2. Движения — из выборки, без запросов в цикле.
       // 3. Контроль остатков — после записи, запросом к остаткам.
   КонецПроцедуры
   ```
3. Правила:
   - Данные для движений — **один пакетный запрос** с временными
     таблицами, не обход табличной части с запросом на каждую строку.
   - `Записывать = Истина` у каждого набора движений; старые движения
     очищаются платформой, вручную не удаляй.
   - **Контроль остатков** при оперативном проведении: сначала управляемая
     блокировка (`БлокировкаДанных`, режим `Исключительный`, поля —
     измерения из табличной части через `ИсточникДанных`), потом запись
     движений, потом запрос остатков `< 0` и `Отказ = Истина` с понятным
     сообщением по каждой строке.
   - Новая методика: `Движения.Регистр.БлокироватьДляИзменения = Истина`
     и проверка остатков после записи наборов.
   - Измерения, ресурсы и реквизиты заполняются явно; `Период` — дата
     документа (или момент для регистров с моментом времени).
   - Неоперативное проведение — без контроля остатков.
   - Сообщения пользователю — с привязкой к полю табличной части.
4. Если пользователь просит написать проведение — выдай модуль целиком в
   блоке кода `bsl` и перечисли, какие регистры и реквизиты задействованы;
   если разобрать существующее — найди ошибки по списку выше
   («Модуль:строка — проблема — исправление»).
