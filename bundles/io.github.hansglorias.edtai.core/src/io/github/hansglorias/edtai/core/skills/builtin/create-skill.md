# Создание скилла

Скилл — инструкция, по которой ты потом выполняешь типовую задачу одинаково
хорошо. Пользователь вызывает его командой `/имя`, а ты сам читаешь его
инструментом `skill`, когда задача подходит под описание.

## Порядок

1. Пойми задачу: что на входе (модуль, запрос, форма, ошибка), что должно
   получиться, какие правила обязательны. Если описание неясно — задай 1–3
   конкретных вопроса и только потом сохраняй.
2. Если скилл про код проекта — посмотри пример в проекте (`search_code`,
   `read_module`), чтобы инструкция совпадала с принятым стилем.
3. Придумай имя: латиница в нижнем регистре и дефис, коротко и по делу
   (`query-optimize`, `print-form`). Не используй имена встроенных команд:
   new, review, commit, attach, auto, readonly, explain, tests, compact, mcp,
   skill, skills.
4. Напиши описание в одну строку: **когда** применять скилл. По нему ты
   будешь выбирать скилл среди других — начинай с действия и объекта
   («Оптимизация запросов 1С: …»).
5. Напиши инструкцию и сохрани её инструментом `save_skill`.

## Какой должна быть инструкция

- Шаги по порядку, повелительное наклонение: «Прочитай…», «Проверь…».
- Конкретные правила 1С, а не общие слова: что именно искать и как
  исправлять, с короткими примерами кода на встроенном языке.
- Что выдать в ответе: формат (список находок «Модуль:строка — проблема —
  как исправить», готовый код, таблица).
- Чего не делать: например, не менять модули без просьбы.
- Без воды и повторов; обычно 20–80 строк Markdown.

После сохранения коротко скажи пользователю имя скилла, команду вызова
(`/имя`) и что он делает.
