# Стиль запросов 1С

Цель: запрос читается как написанный разработчиком. Ревью запросов — по
этим же правилам. Скорость медленного запроса — скилл query-optimize. Если
правило в конкретном случае вредит (замер показал проблему), скажи и
предложи отступить.

## 1. Разыменование через точку вместо лишнего соединения

Реквизит достижим через точку от уже имеющейся ссылки: бери точкой, не
соединяй таблицу ради одного поля. Цепочки `Поле.Реквизит.Реквизит`
нормальны. Соединение оправдано, когда таблица нужна сама по себе (несколько
её полей, агрегаты, отбор по строкам, которых нет в исходной таблице).
Исключение — поле составного типа: точка через него соединяет все таблицы
типа, тогда `ВЫРАЗИТЬ` (п. 4).

```bsl
// Плохо: соединения ради одного поля
ВЫБРАТЬ
	Состав.Сотрудник КАК ФизЛицо,
	Учетка.Логин КАК Логин
ИЗ
	РегистрСведений.СоставКоманды КАК Состав
	ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.ФизическиеЛица КАК ФЛ
		ПО ФЛ.Ссылка = Состав.Сотрудник
	ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.УчетныеЗаписи КАК Учетка
		ПО Учетка.Ссылка = ФЛ.УчетнаяЗапись

// Хорошо
ВЫБРАТЬ
	Состав.Сотрудник КАК ФизЛицо,
	Состав.Сотрудник.УчетнаяЗапись.Логин КАК Логин
ИЗ
	РегистрСведений.СоставКоманды КАК Состав
```

## 2. Временные таблицы вместо подзапросов

Промежуточный набор выноси в `ПОМЕСТИТЬ ВТ_…`, а не прячь в
`В (ВЫБРАТЬ …)`, `СОЕДИНЕНИЕ (ВЫБРАТЬ …)` или в поля. ВТ видно в отладке,
она переиспользуется в следующих запросах пакета, и запрос читается сверху
вниз.

```bsl
// Плохо
ВЫБРАТЬ
	Заявка.Ссылка
ИЗ
	Документ.Заявка КАК Заявка
ГДЕ
	Заявка.Автор В
		(ВЫБРАТЬ Пользователи.Ссылка
		ИЗ Справочник.Пользователи КАК Пользователи
		ГДЕ Пользователи.Недействителен = ЛОЖЬ)

// Хорошо
ВЫБРАТЬ
	Пользователи.Ссылка КАК Пользователь
ПОМЕСТИТЬ ВТ_ДействующиеПользователи
ИЗ
	Справочник.Пользователи КАК Пользователи
ГДЕ
	Пользователи.Недействителен = ЛОЖЬ
;
ВЫБРАТЬ
	Заявка.Ссылка
ИЗ
	Документ.Заявка КАК Заявка
	ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_ДействующиеПользователи КАК ДействующиеПользователи
		ПО ДействующиеПользователи.Пользователь = Заявка.Автор
```

## 3. Без `ИНДЕКСИРОВАТЬ ПО` во временных таблицах

На обычных небольших ВТ индекс не окупается, а в коде это шум. По умолчанию
без индексов; индекс — когда ВТ большая и по ней соединяют, и это видно по
замеру.

## 4. Проверка и известные ловушки

- Перед выполнением проверяй текст: `validate_query` из EDT MCP, если он
  подключён (знает метаданные проекта, база не нужна).
- Псевдонимы — не зарезервированные слова (`Где`, `Как`, `Из`…), перечень в
  скилле bsl-style, п. 4.
- Перечисления в условиях: `ЗНАЧЕНИЕ(Перечисление.Вид.Значение)`.
- Составной ссылочный реквизит: `ВЫРАЗИТЬ(Поле КАК Справочник.X)` плюс отбор
  `Поле ССЫЛКА Справочник.X`.
- «Последняя запись» через соединение по `Дата = МАКСИМУМ(Дата)` даёт дубли,
  если у нескольких строк одно время. Бери агрегаты без детального
  самосоединения.
- Срез последних без параметров и отбора считает по всей таблице: при частом
  вызове (таймер формы) сужай.
- `Запрос.Выгрузить()` сохраняет NULL из левого соединения (динамический
  список превращал его в пустое значение). Переходишь со списка на запрос —
  заменяй NULL явно (скилл platform-gotchas).
