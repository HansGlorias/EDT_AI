# Маршрут работы с проектом

Выбери нужную часть маршрута по цели пользователя. Для объяснения достаточно
исследования и ответа; запрос на чтение не разрешает правки.
Скиллы ниже читай, если они есть в доступном каталоге; отключённые не подменяй.

1. Определи результат и критерии: какое поведение требуется, что уже известно,
   какие факты нужны. Связи нескольких модулей исследуй по project-navigation;
   известное локальное место прочитай напрямую.
2. До написания или исправления запроса 1С, включая строку внутри BSL и СКД,
   прочитай query-development. Для BSL используй bsl-style; для формы,
   клиент-серверного перехода и других особенностей — относящиеся к работе
   доступные скиллы. Не загружай весь справочник ради одной правки.
3. Неизвестный метод, сигнатуру и тип проверь адресной справкой/API-инструментом;
   имена объектов и полей — метаданными проекта. Используй уже предложенные
   схемы; остальные найди и выбери через discover_mcp_tools. Отсутствие схемы
   в текущем наборе ещё не означает отсутствие возможности на сервере.
4. Внеси разрешённое изменение, перечитай результат и выполни подходящие
   проверки итоговой редакции. Для BSL check_module даёт снимок диагностик:
   пустой снимок не подтверждает завершённую проверку. Сверь diff и критерии
   задачи, включая ошибки, пустые данные и границы там, где они существенны.
5. В итоге различай выполненные изменения, фактические проверки и оставшееся
   непроверенным. Успех вызова инструмента не равен правильности кода.
   Исправляй по диагностике; если новые попытки не дают фактов, назови блокер.

Это маршрут ведущего. Обычную проверку инструментом выполняй напрямую;
специалист нужен для отдельной задачи исследования или независимой сверки.
