# Стиль кода 1С (BSL)

Цель: код читается как написанный разработчиком команды, без «защитного»
обвеса и без признаков нейросети. Ревью веди по этим же правилам. Стиль
запросов — в скилле query-style, проверка по стандартам 1С — code-standards.

Применяй по умолчанию. Если правило в конкретном месте вредит, не делай
молча наоборот: скажи и предложи отступить.

## 1. Без управляемых блокировок по своей инициативе

`Новый БлокировкаДанных` и `.Заблокировать()` ставь, только если об этом
просят или блокировка нужна наверняка (конкретная гонка, без которой данные
точно поедут). «Защитная» блокировка на всякий случай — лишний код. Видишь
возможную гонку, но не уверен: не блокируй молча, скажи о риске и спроси.

## 2. Комментарии скупо

Обильные комментарии — первое, по чему видно, что код писал не человек.

- **Описание у экспортных методов** в формате БСП (`Параметры:`,
  `Возвращаемое значение:`, скилл method-docs): это публичный интерфейс.
- **Внутри тела — только по реальному поводу:** почему выбран такой способ,
  какой баг лечится, какое ограничение платформы обходится. Не пересказывай
  код.
- Ориентир: модуль на ~200 строк — около десятка комментариев, почти все —
  шапки экспортных методов. Внутри тел больше двух-трёх: перечитай и выкинь
  лишнее.
- То же для комментариев в метаданных: строка там, где имя не раскрывает
  смысл, и ничего там, где раскрывает.
- Простые слова, без «идемпотентно», «инвариант» и англицизмов при живом
  русском слове.

```bsl
// Хорошо: объясняет причину, из кода её не видно
// Обе записи в одной транзакции, иначе при сбое признак заполненности соврёт.
НачатьТранзакцию();

// Плохо: пересказ
// Получаем объект справочника
ОбъектЗаписи = Ссылка.ПолучитьОбъект();
```

## 3. Имена

- **По имени понятно, к чему относится значение.** «СтрокаАктивна» — какая
  строка, где? Лучше `ОтборПоПространствуНаВкладкеПользователи`.
- **Без сокращений:** `ОбновитьТехническоеИмяСлужб`, а не `ОбновитьТехИмяСлужб`.
- **Без выдуманных обобщений**, которых нет в предметной области: вместо
  «координат» узла — хост, порт, имя базы, строка подключения.

## 4. Имена переменных не совпадают со свойствами контекста

Локальная переменная с именем свойства формы или объекта — не новая
переменная, а запись в свойство. Компилятор молчит, падает при выполнении и
часто только у части пользователей. Живой случай: `Доступность = Новый
Соответствие` в модуле формы писало в свойство формы — «Несоответствие
типов» у всех, кроме администраторов.

- **Модуль формы:** `Доступность`, `Заголовок`, `ТолькоПросмотр`,
  `Модифицированность`, `Элементы`, `Команды`, `Параметры`, `ВладелецФормы`,
  `КлючУникальности`, `КлючНазначенияИспользования`, `ТекущийЭлемент`,
  `РежимОткрытияОкна`, `ЗакрыватьПриВыборе`, `ЗакрыватьПриЗакрытииВладельца`,
  `ИмяФормы`, `Окно`, `АвтоЗаголовок`, `Ширина`, `Высота`, `Группировка`,
  `ЭтаФорма`, `ЭтотОбъект`; плюс все реквизиты формы (`Объект`, `Список`,
  `Запись` и свои — `<attributes>` в `Form.form`). `&НаСервереБезКонтекста`
  от этого защищён, `&НаСервере` и `&НаКлиенте` — нет.
- **Модуль объекта и набора записей:** `Ссылка`, `Код`, `Наименование`,
  `Родитель`, `Владелец`, `ПометкаУдаления`, `Предопределенный`, `Дата`,
  `Номер`, `Проведен`, `ВерсияДанных`, `ОбменДанными`,
  `ДополнительныеСвойства`, `Отбор`; плюс все реквизиты и табличные части.
- **Глобальный контекст:** `Справочники`, `Документы`, `Перечисления`,
  `РегистрыСведений`, `РегистрыНакопления`, `Константы`, `Обработки`,
  `Отчеты`, `БизнесПроцессы`, `Задачи`, `ПланыОбмена`,
  `ПланыВидовХарактеристик`, `Метаданные`, `ПараметрыСеанса`,
  `РегламентныеЗадания`, `ФоновыеЗадания`, `ПользователиИнформационнойБазы`,
  `ХранилищеОбщихНастроек`, `БиблиотекаКартинок`, `БиблиотекаСтилей`,
  `ЦветаСтиля`, `ШрифтыСтиля`, `WebЦвета`, `WindowsЦвета`, `Символы`,
  `РабочаяДата`, `ГлавныйИнтерфейс`.
- **Общие модули** (переменная заслоняет модуль до конца процедуры):
  `Пользователи`, `ОбщегоНазначения`, `Взаимодействия`, `РаботаСФайлами`,
  `ВариантыОтчетов`, `ДлительныеОперации`, `УправлениеДоступом`,
  `ОбновлениеИнформационнойБазы`, `УправлениеПечатью`. Полный перечень —
  `list_objects` по общим модулям.
- **Зарезервированные слова** (и в коде, и как псевдонимы в запросах):
  `Знач`, `Перем`, `Новый`, `Выполнить`, `Где`, `Как`, `Из`, `Выбрать`,
  `Различные`, `Первые`, `По`, `Итоги`, `Выбор`, `Когда`, `Тогда`, `Иначе`,
  `Конец`, `Между`, `Подобно`, `Есть`, `Иерархия`. `КАК Ссылка`,
  `КАК Количество` можно — так пишет БСП.

Предметное имя из п. 3 почти всегда само уводит от совпадения:
`ВидимостьКоманд`, `СписокПользователей`, `СтатусЗаявки`, `ТекстОшибки`.

## 5. Без переменных модуля формы, если можно обойтись

Не заводи `Перем` в модуле формы, чтобы протащить состояние между
процедурами. Сначала: перечитать значение там, где нужно, передать
параметром, вернуть из функции. Переменная модуля — последний вариант, и его
надо объяснить: скрытое состояние живёт дольше нужного и превращается в
мёртвый код.

Если переменная всё же нужна: директива компиляции действует на одно
объявление. `&НаКлиенте` перед блоком из трёх `Перем` делает клиентской
только первую. Ставь директиву каждой.

## 6. В обработчиках событий — условие вокруг блока, а не ранний `Возврат`

Часть обработчика (`ПередЗаписью`, `ПриЗаписи`, `ПриСозданииНаСервере`…)
нужна только в каком-то случае: оборачивай в `Если … Тогда … КонецЕсли`. В
обработчик потом допишут код, и ранний выход молча его отрежет.

```bsl
// Хорошо
Процедура ПередЗаписью(Отказ)
	Если Статический Тогда
		ПроверитьДубль(Отказ);
	КонецЕсли;
КонецПроцедуры

// Плохо
Процедура ПередЗаписью(Отказ)
	Если Не Статический Тогда
		Возврат;
	КонецЕсли;
	ПроверитьДубль(Отказ);
КонецПроцедуры
```

Ранний выход в своей служебной функции с одной задачей (проверка входных
параметров) допустим.

## 7. Привилегированный режим — последнее средство

- Не хватает прав на действие: решай ролями (роль в профиль, технический
  пользователь с ролью без РЛС), а не привилегированным режимом. Подробно —
  скилл access-rights.
- Привилегии остаются только там, где без них не работает платформа или БСП
  (безопасное хранилище данных).
- Если нужен: включай прямо перед операцией и сразу выключай, не в начале
  функции «на всякий случай».

```bsl
УстановитьПривилегированныйРежим(Истина);
Значение = ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(Владелец, Ключ);
УстановитьПривилегированныйРежим(Ложь);
```

## 8. Плоско и прямо

Страх ревьюера: «у нас всё работает, но мы не понимаем как».

- Минимальная глубина вызовов. Цепочка «форма → клиентский модуль → вызов
  сервера → менеджер → ещё функция → ещё функция» — уже плохо.
- Не передавай структуру с набором параметров, где ключи зависят от
  вызывающего. Явные параметры или два явных метода лучше одного
  универсального с `ИмяСвойства` или `Режим`.
- Помощник заводи, когда он реально переиспользуется и упрощает место
  вызова. Иначе пиши на месте.
- Метод с единственным вызывающим держи в модуле вызывающего, закрытым, а
  не экспортом в менеджере.
- Меньше новых экспортных методов в общих модулях. Модулей тоже минимум
  (`Подсистема`, `ПодсистемаВызовСервера`, `ПодсистемаКлиент`), внутри —
  области.
- Новую ошибку чини упрощением существующего кода, а не ещё одной прослойкой.
- Перед сдачей перечитай цепочку вызовов глазами ревьюера.

## 9. Мелочи, которые сокращают код

- `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Ссылка, "Родитель.Реквизит")` —
  реквизит через точку, один вызов вместо двух.
- Полноправность — `Пользователи.ЭтоПолноправныйПользователь()`, а не
  `РольДоступна("ПолныеПрава")`.
- Значения из кэшей и данных формы проверяй наличием поля
  (`Данные.Свойство("Ссылка")`), а не типом: там бывает
  `ДанныеФормыСтруктура`, а не `Структура`.

Грабли платформы, которые не про стиль, — скилл platform-gotchas.
