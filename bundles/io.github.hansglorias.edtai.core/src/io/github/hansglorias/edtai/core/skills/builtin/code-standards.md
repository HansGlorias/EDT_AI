# Проверка модуля на стандарты 1С

Прочитай модуль целиком (`read_module`). Проверь по пунктам и выдай
находки списком «Модуль:строка — что не так — как исправить», от важного к
мелкому. В конце — 2–3 строки общего вывода.

## Структура и оформление
- Области: `ПрограммныйИнтерфейс`, `СлужебныйПрограммныйИнтерфейс`,
  `СлужебныеПроцедурыИФункции` (в модулях форм — `ОбработчикиСобытийФормы`
  и т. д.). Экспортные методы — только в программном интерфейсе.
- У экспортных методов — комментарий: описание, `Параметры:`,
  `Возвращаемое значение:` (см. скилл method-docs).
- Имена — по смыслу, без сокращений и транслита; переменные не
  переиспользуются для разных целей.
- Нет закомментированного мёртвого кода, длинных методов (> 100–150
  строк) и глубокой вложенности — предложи выделить методы.

## Ошибки и транзакции
- `Попытка … Исключение` не глушит ошибки: в `Исключение` — запись в журнал
  (`ЗаписьЖурналаРегистрации` с `ПодробноеПредставлениеОшибки`) и/или
  `ВызватьИсключение`.
- Транзакция: `НачатьТранзакцию()` прямо перед `Попытка`,
  `ЗафиксироватьТранзакцию()` — последней строкой в `Попытка`, в
  `Исключение` — `ОтменитьТранзакцию()` и `ВызватьИсключение`. Внутри
  транзакции нет интерактива и долгих вычислений. Управляемая блокировка —
  там, где без неё данные поедут (чтение остатков перед записью), а не «на
  всякий случай» (скилл bsl-style, п. 1).
- Нет `Сообщить()` в серверном коде для ошибок — `ОбщегоНазначения.
  СообщитьПользователю` (если есть БСП) или исключение.

## Производительность
- Нет запросов и обращений через точку к ссылкам в цикле (см. скилл
  query-optimize).
- Нет лишних серверных вызовов с клиента (см. скилл client-server).

## Прочее
- Строки для пользователя — через `НСтр("ru = '…'")`.
- Нет «магических» строк и чисел: имена метаданных, предопределённые
  значения — через `ПредопределенноеЗначение`, `Метаданные`.
- Привилегированный режим и `УстановитьПривилегированныйРежим` — только
  где нужно, узким окном, с комментарием почему (скилл access-rights).
- Стиль — по скиллу bsl-style: скупые комментарии, плоские вызовы, имена не
  совпадают со свойствами формы и объекта.

Модуль не правь без просьбы; если пользователь попросит исправить — правь
по одной находке через `edit_module`.
