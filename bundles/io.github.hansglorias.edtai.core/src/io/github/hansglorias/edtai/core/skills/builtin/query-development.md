# Написание и проверка запросов 1С

1. Установи проект, поля, параметры и критерии выборки. Неизвестные имена
   проверь по метаданным. Стиль — query-style, если доступен.
2. Язык запросов отличается от BSL и других SQL: ПЕРВЫЕ после ВЫБРАТЬ,
   УПОРЯДОЧИТЬ ПО. Неизвестную функцию проверь по справке, не угадывай.
3. Вызови доступный validate_query; если схемы нет, найди и выбери её через
   discover_mcp_tools. Используй опубликованное имя и фактическую схему;
   при неясности — доступный get_tool_guide. СКД проверяй в поддерживаемом
   режиме dcsMode. Выполнение в базе ради синтаксиса не требуется.
4. После записи перечитай все изменённые запросы. Проверь точный итоговый
   текст: кавычки, продолжения, %, параметры. modulePath читает сохранённый
   модуль; dirty-буфер передай через queryText, если доступен. Динамические
   и пропущенные части обозначь непроверенными. Любая правка отменяет
   прежнюю проверку.
5. DONE/success=true — успех вызова. Проверь valid, ошибки и, если есть,
   validationState: VALID/INVALID/PARTIAL; для модуля — каждый queries[].
   Исправляй по диагностике; повтор без новых фактов прекрати с блокером.
6. Сверь отборы, сортировку, дубли, пустой результат и границы с задачей.
   В ПОДОБНО/LIKE % — произвольная последовательность; его потеря меняет
   выборку. Синтаксис не доказывает поведение. Назови проверенный текст,
   результат и ограничения; отличай разбор случаев от проверки на данных.

Нет валидатора — сообщи, что инструментальная проверка не выполнена.
