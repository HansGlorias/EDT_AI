# Исследование проекта

Применяй, когда ответ требует установить связи между несколькими модулями
или объектами. Для локального вопроса с известным местом кода достаточно
адресного чтения. Эта методика подходит ведущему и читающему исследователю;
роль исследователя не разрешает запись и повторное делегирование.

## 1. Цель и проверяемые вопросы

Выдели требуемый результат и неизвестное. Разбей задачу на несколько вопросов,
ответы на которые нужны для следующего действия. Используй переданные факты
и точки входа; не начинай поиск проекта заново без причины. Если область
неоднозначна, установи проект и объект, прежде чем делать выводы.

## 2. От структуры к нужному коду

1. Найди объекты и точки входа доступными сведениями о проекте, списком объектов
   и адресным поиском. Различай поиск текста и проверенную связь вызовов.
2. По найденным ссылкам прочитай нужные участки модулей и вызываемый код.
   Небольшой модуль можно читать целиком. У большого сначала определи нужные
   методы по поиску или доступной структуре; затем читай их диапазоны.
3. Учитывай запрошенный и фактически полученный объём. Страница снимка —
   часть результата; read_tool_result дочитывает снимок, не обновляет исходник.
4. Для структуры формы, свойств метаданных и определения API найди подходящие
   разрешённые MCP-инструменты через discover_mcp_tools и подключи их схемы.
   При отсутствии нужной возможности назови пробел. Не выдумывай инструмент
   или метод платформы. Ведущий может прочитать другой подходящий скилл через skill.

## 3. Факты и продвижение

- Для существенного вывода сохрани подтверждение: файл/объект, метод и строки.
  Наличие имени в старом коде не подтверждает существование объекта сегодня.
  При пустом поиске проверь проект, тип и точное имя; различай «не найдено
  этим поиском» и подтверждённое отсутствие. Опровержение инструментом сохраняй.
- Не перечитывай тот же текст с другой нотацией пути ради продолжения работы.
  Повтор нужен при изменении исходника, недополученной области или проверке
  конкретного противоречия. Объясни себе, какой новый факт ожидаешь получить.
- Если несколько попыток не дали новых данных, смени способ проверки или
  верни конкретный блокер и частичные факты. Не продолжай обход монолита
  ради числа прочитанных строк; не обещай выполненную правку по чтениям.
- Останавливай исследование, когда вопросов достаточно для следующего
  действия. Независимые чтения можно запросить одним пакетом; пакет
  исполняется последовательно и не означает параллельную работу агентов.

## 4. Результат исследования

Верни компактно:
- проверяемый вопрос → подтверждённый факт → ссылка файл/объект:строки;
- важные связи и точки входа для следующего действия;
- противоречия, предположения и то, чего не удалось проверить;
- при неполном результате — причину и минимальную следующую проверку.

Отчёт не заменяет проверку актуальности кода. Ведущий использует найденные
факты, адресно проверяет спорное и перечитывает целевой участок перед записью.
Не передавай дочерние snapshot ID: у ведущего нет доступа к этим снимкам.
