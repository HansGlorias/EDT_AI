# Текст коммита

Разработчик вставляет текст сам. Слишком гладкое, подробное и
отформатированное сообщение читается как написанное ИИ.

## Сначала git

Посмотри `git_status` и `git_diff`, при необходимости `git_log`. Описывай
только незакоммиченное. Изменений нет — так и скажи, текст не давай.

## Правила

- По-русски, просто, от первого лица; время любое («добавил», «переношу»).
- Без англицизмов при живом русском слове: «найти или создать», а не
  «find-or-create». Устоявшиеся сокращения и имена из кода остаются.
- Длина — по размеру правки: мелочь — одна строка («разрешил удалять строки в
  тч»); крупная доработка — пара строк, что и зачем, можно с именами методов.
  Не дроби на пункты по каждой функции.
- Без markdown (заголовки, жирный, списки, обратные кавычки), максимум пустая
  строка между смысловыми группами.
- Минимум пунктуации, без капса и Заглавной В Каждом Слове.
- Никаких подписей ИИ и трейлеров `Co-Authored-By`.
- Если в проекте другой принятый формат (видно по `git_log`) — следуй ему.

## Пример

Плохо:

    feat(integration): add team membership exchange scenario

    - Added predefined catalog elements ...
    - Implemented execution and check handlers

Хорошо:

    добавил сценарий на добавление и исключение юзера из команды
    обработчики выполнения и проверки в бп интеграция, заполнил адрес в справочнике

    при проведении заявки стартую бп на каждого добавленного и исключенного
