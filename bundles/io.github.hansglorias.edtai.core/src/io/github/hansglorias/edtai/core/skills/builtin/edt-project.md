# Работа с проектом EDT

Источник правды — файлы EDT-проекта в git. Модуль правишь `edit_module`,
разработчик смотрит изменения («Изменения» под ответом), обновляет базу из
EDT и коммитит сам.

## 1. Проверка после правки

`edit_module` пишет через EDT: правка сразу видна в редакторе и модели EDT.
Если подключён EDT MCP (инструменты EDT-MCP в списке), после правки:

1. `revalidate_objects` по изменённому объекту (`Catalog.Имя`,
   `DataProcessor.Имя`…).
2. `read_method_source` — модель EDT видит новый код.
3. `validate_form_model`, если менялась форма.
4. `get_project_errors` с фильтром по объектам, сначала только ошибки. После
   правки клиентского кода смотри и без фильтра важности, но только свои
   строки: так ловится недоступность метода в контексте (`undefined-function`
   для серверного метода в клиентском коде).
5. Сравнивай с тем, что было до правки. Чужие старые предупреждения не чини.

Кроме проверки полезны: `search_in_code`, `find_references`,
`go_to_definition`, `get_method_call_hierarchy`, `get_module_structure`,
`get_metadata_details`, `validate_query`, `get_platform_documentation`.

Правки файлами мимо EDT (инструменты MCP, которые пишут на диск) EDT видит не
сразу: попроси обновить проект (F5), иначе в базу уедет старый код. Открытые
вкладки с несохранёнными изменениями при сохранении затрут правку —
предупреди.

**Опасные операции — только по просьбе:** `resync_to_disk`, `clean_project`,
обновление базы, запуск, удаление объектов, переключение веток.

## 2. Метаданные файлами

- **Новый объект в `Configuration.mdo` — в конец списка своего вида**
  (`<catalogs>`, `<roles>`…), как делает сам EDT. Не по алфавиту.
- **Режим совместимости** (`<compatibilityMode>` в `Configuration.mdo`)
  ограничивает язык: метод, появившийся позже, «не обнаружен» на любой
  платформе. Сверяйся до того, как брать свежий метод.
- **Идентичность объектов — по UUID, а не по имени.** Объект, перенесённый
  копированием, получает новые UUID реквизитов, и данные базы к нему не
  подхватятся. Нужен перенос с сохранением: бери исходный `.mdo` и меняй
  только имена и синонимы.
- **Правишь форму — убедись, что она используется:** `defaultForm` в `.mdo`
  объекта и вызовы `ОткрытьФорму`. Старая форма может выглядеть живой.
- `ЗначенияЗаполнения` игнорируются, если у реквизита не стоит
  `fillFromFillingValue`.
- У динамического списка с основной таблицей ключ строки — ссылка; основная
  таблица в `Form.form` иногда слетает, и ключи перенумеровываются на каждом
  чтении. При странных дублях в списке сначала проверь основную таблицу.
- `Rights.rights` с `setForNewObjects=true`: в файле лежат только снятые
  права, неперечисленные объекты получают все. Подробно — скилл access-rights.
- Команда в меню «Ещё»: у кнопки `locationInCommandBar = InAdditionalSubmenu`.
  Сочетание клавиш Escape пишется `Esc`.

## 3. Содержимое файлов

- **Никаких управляющих символов в макетах** (NUL и т. п., даже внутри
  JS-строки): текст макета сериализуется в XDTO, и `ПолучитьФорму` падает с
  «Текст XML содержит недопустимый символ».
- Разные версии EDT пишут файлы по-разному (порядок прав, `fillValue`, новые
  свойства): такой шум в сравнении не путай с реальными изменениями.

Платформенные грабли — скилл platform-gotchas.
