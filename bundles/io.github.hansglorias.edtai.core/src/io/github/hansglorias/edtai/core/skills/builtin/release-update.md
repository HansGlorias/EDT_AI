# Релизы, обработчики обновления, перенос

## 1. Версия

- Проставляй версию **сразу во всех местах** одной правкой: обычно
  `Configuration.mdo` → `<version>`, `ПриДобавленииПодсистемы` →
  `Описание.Версия` и версия обработчика с именем процедуры
  (`ПерейтиНаВерсию_<версия через подчёркивания>`).
- Номер бери по правилу проекта (спроси, если не знаешь), а не «следующий за
  прошлым».
- Сверяйся со свежей основной веткой: локальная отстаёт, номер окажется
  занят или ниже текущего.

## 2. Один обработчик на релиз

- Всё, что сделано в ветке до релиза, складывай в ОДИН обработчик релизной
  версии, добавляя в него шаги. Порядок шагов — за тобой, там же короткий
  комментарий, почему такой.
- **Версию никогда не опускай.** Если на тестовой базе в `ВерсииПодсистем`
  уже записана x.3, а в конфигурации поставить x.1, будущие x.2 и x.3 на
  этой базе не отработают никогда. Пропуск номеров безвреден, откат — нет.
- Шаги делай повторяемыми: проверка «уже сделано» перед записью. Обработчик
  может пойти повторно.
- **Не меняй массово статусы и состояния объектов** в обработчиках: они могут
  быть легитимными.
- Не повторяй шаги, которые при повторе воскрешают удалённое или сбрасывают
  пользовательские настройки.
- Массовое изменение данных в обработчике — только после согласия
  разработчика.

## 3. Слияние веток конфигурации

- **Цепочки обработчиков разъезжаются молча.** Если целевая база стоит на
  версии выше, чем ваши обработчики, БСП их пропустит, включая нужные
  миграции. Перед заливкой перерегистрируй их под новой версией.
- **Идентичность объектов — по UUID, а не по имени.** Скопированный объект
  получает новые UUID, данные к нему не подхватятся. Переименования объектов
  регистрируются отдельно (`ПриДобавленииПереименованийОбъектовМетаданных`),
  иначе настройки по старому имени потеряются.
- Сравнивай с тем, что реально стоит на проде, а не с веткой, которая
  «примерно прод».
- Шум формата от разных версий EDT (порядок прав, `fillValue`, новые
  свойства) отделяй от реальных изменений.

## 4. Отчёт о переносе

Найденное раскладывай на три группы: ошибки слияния (наши, чиним), старые
ошибки целевой конфигурации (помечаем, можно подправить), доработки (не
делаем, откладываем отдельным списком).
