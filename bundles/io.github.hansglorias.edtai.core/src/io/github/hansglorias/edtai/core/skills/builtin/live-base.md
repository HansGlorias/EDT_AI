# Живая база через MCP

## 1. Два вида серверов

| | 1c-mcp-toolkit | mcp-1c |
|---|---|---|
| как работает | внешняя обработка в открытом сеансе 1С, HTTP на localhost | сервис плюс расширение с HTTP-сервисом в базе |
| доступность | только пока открыт сеанс и обработка | всегда |
| контекст | клиентский и серверный: открыть форму, скриншот | только серверный |
| права | код без безопасного режима | безопасный режим: привилегированный режим не действует, безопасное хранилище не читается, `HTTPСоединение` запрещено |
| особенности | «опасный» код ждёт подтверждения в окне 1С | после обновления конфигурации может держать старый скомпилированный код |

Ни один не отдаёт тексты модулей и не пишет исходники: код читай из проекта
(`read_module`) или через EDT MCP.

По умолчанию: выполнение кода, запись, формы — через toolkit; чтение
метаданных и SELECT можно через mcp-1c. Если пользователь назвал сервер —
работай через него (имена инструментов пересекаются, различай по серверу).

## 2. Сначала проверь, какая это база

Серверы могут смотреть в разные базы, и это меняется от запуска к запуску.
Проверяй каждый раз перед разбором данных:

```bsl
Результат = СтрокаСоединенияИнформационнойБазы();
```

Выводы, снятые на одной базе, к другой не применяй. В ответе говори, с какой
базы данные.

## 3. Ловушки

- **mcp-1c держит старый код после обновления конфигурации,** а данные отдаёт
  свежие. Новые данные видны, а новая функция ведёт себя как до правки —
  проверь тем же вызовом через toolkit, а не гони «обновить базу».
- **Безопасный режим mcp-1c не снимай** (`УстановитьБезопасныйРежим(Ложь)`):
  это обход песочницы.
- **toolkit: код со словом `Удалить`** (даже `ТЗ.Удалить(1)`) и
  `Новый COMОбъект` ждёт подтверждения в окне 1С. Без разработчика обходи:
  строки убирай пересборкой таблицы, объекты — пометкой удаления.
- **toolkit `execute_code`** возвращает значение переменной `Результат`;
  объявлять процедуры и писать `Возврат` внутри нельзя.
- Переменную не называй `Окно` и другими зарезервированными именами (скилл
  bsl-style, п. 4).
- Сервер не отвечает — попроси поднять сервис; кнопка MCP в поле ввода
  покажет, подключился ли он.

## 4. Приёмы проверки кодом в базе

- **Изменение данных гоняй в транзакции и откатывай:** `НачатьТранзакцию()` …
  отчёт … `ОтменитьТранзакцию()`.
- **Права другого пользователя:** `ПравоДоступа(Право, ОбъектМетаданных,
  ПользователиИнформационнойБазы.НайтиПоИмени(…))` (без РЛС). РЛС проверяй по
  группам и значениям доступа.
- **Большие данные** не тащи через ответ: пусть база пишет и читает JSON во
  временной папке.
- **После массового создания данных** сверяй результат отдельным чтением:
  модуль типового объекта может молча очистить поля при записи.

## 5. Живые данные

Каждая цифра в ответе о данных должна прийти из вызова в этот момент. Память и
прошлые ответы — только направление.
