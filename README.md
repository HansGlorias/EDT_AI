# EDT AI

Плагин для 1C:EDT: чат с языковой моделью прямо в IDE. Рассчитан в том числе
на закрытый контур: адрес модели задаётся в настройках, корпоративный CA
подключается PEM-файлом, токен хранится в Eclipse Secure Storage.

**Сейчас — этапы 4–6 (5 и 6 — MVP).** Чат отвечает настоящей моделью по OpenAI-совместимому
протоколу или Anthropic Messages, ответ появляется по мере генерации и
показывается с оформлением Markdown, код из ответа копируется или
вставляется в редактор одним щелчком, диалог переживает перезапуск EDT.
Код из модуля прикрепляется к вопросу по Ctrl+Alt+A: модель видит его и
знает, из какого он объекта метаданных. Модель может и сама посмотреть
проект: сведения о конфигурации, список объектов, текст модуля, поиск по
коду — только чтение. И вызвать инструменты MCP-серверов, например
[EDT-MCP](https://github.com/DitriXNew/EDT-MCP) — с вашего разрешения.
План в [SPEC.md](SPEC.md).

Поддерживаемые версии: 1C:EDT 2025.2 и 2026.1 (Eclipse 4.30, Java 17),
Windows и Linux (в том числе Astra Linux).

## Что есть

- **Window → Show View → Other… → EDT AI → EDT AI** или значок **EDT AI** в
  строке состояния внизу окна EDT (рядом с виджетами других плагинов).
  - Enter — отправить, Shift+Enter — новая строка. Поле ввода растёт до 10
    строк, ↑ / ↓ в пустом поле — ранее отправленные сообщения.
  - Ответ показывается с оформлением: заголовки, жирный и курсив, списки,
    таблицы, цитаты, ссылки (открываются во внешнем браузере). Код —
    шрифтом редактора на фоне, над блоком кода — «Копировать» и «Вставить
    в редактор» (заменяет выделение в открытом модуле с отступом текущей
    строки, Ctrl+Z отменяет).
  - У сообщений: «Копировать» (ответ в Markdown), «Повторить» (последний
    ответ), «Изменить» (своё сообщение возвращается в поле ввода, всё после
    него убирается).
  - Пока модель отвечает, кнопка становится «Стоп» (или Esc в поле ввода):
    полученная часть ответа остаётся.
  - На панели вида: «Новый чат», «История чатов» и «Настройки». Диалоги
    сохраняются в рабочей области
    (`.metadata/.plugins/io.github.hansglorias.edtai.ui/chats/`), открытый
    восстанавливается при следующем открытии.
  - У строки вызова инструмента — токены шага модели, на котором она его
    вызвала: «· ↑12k ↓310» (≈ — сервер не прислал usage, оценка). Сумма за
    ответ — как раньше, в строке состояния.
  - Ошибка вызова инструмента — с видом: «нет такого инструмента»,
    «неверные аргументы», «повтор, не выполнен», «отклонено», «сервер
    недоступен», «нет ответа», «ошибка инструмента», «прервано»; длинный
    текст ошибки — целиком в подсказке при наведении.
  - Режим вопроса — кнопка «Режим» рядом с моделью или команды `/answer`,
    `/options`, `/recommend`, `/plan`: прямой ответ, варианты с плюсами и
    минусами, рекомендация с обоснованием или план без правок проекта.
    Действует на один вопрос; `/plan текст` — сразу отправить в режиме.
  - Чаты параллельны: пока модель отвечает, можно открыть другой чат или
    начать новый — ответ допишется в фоне, в списке чатов у него
    «отвечает…». Вопрос о разрешении инструмента из фонового чата ждёт,
    пока чат откроют.
  - Панель «История чатов»: поиск по названиям и тексту сообщений (все
    слова, без учёта регистра), в контекстном меню — «Переименовать…» (F2;
    пустое название — снова по первому вопросу), «Экспорт в Markdown…»,
    «Удалить». То же для открытого чата — в меню вида (▾).
  - Внизу строка состояния: модель, сервер, идёт ли генерация.
- **Подменю «EDT AI»** в контекстном меню редактора модуля: «Спросить о
  выделенном» (Ctrl+Alt+A — прикрепить и написать вопрос самому),
  «Объяснить», «Ревью» (по скиллам bsl-style и code-standards, код не
  правится) и «Рефакторинг» (по bsl-style, модель правит модуль — правку
  видно в «Изменения», откатить — «Откатить»). Три последних отправляют
  вопрос сразу; если модель ещё отвечает — в очередь.
- **Кнопка в окне коммита** (Git Staging, значок EDT AI на его панели):
  модель смотрит незакоммиченное по скиллу commit-message, ответ виден в
  чате, а текст сообщения встаёт в поле «Commit Message».
- **Спросить о коде — Ctrl+Alt+A** или **«Спросить AI о выделенном»** в
  контекстном меню редактора модуля:
  - есть выделение — к вопросу прикрепляются выделенные строки (целиком);
  - нет выделения — процедура или функция под курсором вместе с
    комментарием и аннотацией над ней; курсор вне метода — модуль целиком.

  Фрагмент появляется над полем ввода с именем объекта:
  «Справочник.Номенклатура.МодульОбъекта: 10–25». Щелчок по подписи
  открывает модуль на этих строках, «×» убирает фрагмент. Код берётся в
  момент отправки, вместе с несохранёнными правками; строки не сбиваются,
  если выше что-то дописали. Модель получает код с путём и номерами строк,
  в ленте под вопросом — только подписи фрагментов (ссылками).
  «Изменить» возвращает в поле ввода и вопрос, и фрагменты.
  Сочетание клавиш меняется в **Window → Preferences → General → Keys**
  (команда «Спросить AI о выделенном», категория EDT AI).
- **Инструменты.** На вопросы о проекте («что это за конфигурация», «где
  вызывается процедура Х») модель сама вызывает инструменты чтения:
  сведения о проекте из `Configuration.mdo`, список объектов метаданных,
  текст модуля, поиск по коду модулей. Что она прочитала, видно в ленте
  строками «→ Читает модуль … — строки 1–120 из 120». Выключается в
  настройках.
- **Правка модулей.** Если попросить изменить код, модель сама правит
  модули `.bsl` (`edit_module`: заменяет точный фрагмент) — без вопроса
  на каждую правку, как в Claude Code; что изменено, видно в ленте
  («→ Правит модуль … — строки 5–7»), в git и в редакторе (Ctrl+Z).
  Файл без ваших несохранённых правок сохраняется сразу; если такие
  правки есть — изменение остаётся в редакторе несохранённым. Метаданные
  (`.mdo`) модель не меняет.
- **Git.** Если проект в git-репозитории, модель видит, что изменено
  (`git_status`), дифф незакоммиченных правок или коммита (`git_diff`) и
  историю проекта или модуля (`git_log`) — через JGit из EDT, программа
  `git` не нужна. Откатить незакоммиченные изменения файла или объекта
  к последнему коммиту модель может инструментом `git_restore` — с
  подтверждением, как вызовы MCP (в авторежиме — без). Коммитит человек.
- **«Изменения» и «Откатить»** у ответа, где модель что-то меняла: правки
  модулей через `edit_module` — относительно состояния до ответа; файлы,
  изменённые инструментами MCP (формы, метаданные, модули через EDT-MCP), —
  относительно последнего коммита git. В меню вида чата (▾):
  **«Ревью моих изменений»** и **«Сообщение коммита»**.
- **«Прикрепить модуль…»** на панели вида: поиск модуля по имени объекта
  («Номенклатура», «ОбщМод» — по началам слов) или по пути; модуль
  прикрепляется целиком. То же в поле ввода: **`@`** и начало имени —
  список модулей, выбранный прикрепляется.
- **Очередь**: пока модель отвечает, можно писать дальше — Enter (или
  стрелка у поля) ставит сообщение в очередь, оно уйдёт само после
  ответа. Очередь — над полем ввода: «изменить» вернёт сообщение в поле,
  «×» уберёт. Если ответ остановить (Esc, квадрат при пустом поле) или он
  оборвётся, сообщения из очереди вернутся в поле ввода — ничего не
  отправится само. ↑ в пустом поле — прошлые вопросы.
- **Выбор модели** — кнопка с именем модели справа в поле ввода, рядом
  с «Отправить»: список моделей сервера (`/models`) и недавние, внизу —
  «Обновить список» и «Настройки модели…». Или `/model часть-имени`:
  выбирается единственная подходящая; если сервер не отдаёт список —
  берётся имя как набрано. Новая модель — со следующего вопроса, для всех
  чатов (это поле «Модель» в настройках).
- **Команды `/`** в начале сообщения (список появляется сам): `/new` —
  новый чат, `/review [что смотреть]` — ревью незакоммиченных изменений,
  `/commit` — сообщение коммита, `/attach` — прикрепить модуль, `/auto` —
  авторежим, `/readonly` — только вопросы, `/explain [что]` — объяснить
  код, `/tests [что]` — тесты для кода (YAxUnit или то, что уже есть в
  проекте; код — в ответе), `/compact` — сжать историю сейчас, `/model` — сменить модель, `/mcp` —
  окно MCP-серверов: состояние подключения, инструменты каждого сервера —
  какие читают, какие меняют проект, какие не передаются модели по
  фильтру, внизу полное описание выбранного, кнопка «Настройки MCP…». `/explain` и `/tests` берут прикреплённый код, а если его нет —
  выделение или метод под курсором в редакторе (как Ctrl+Alt+A).
- **Файлы и скриншоты**: кнопка со скрепкой рядом с полем ввода (несколько
  файлов сразу) или «Приложить файлы…» в его контекстном меню, Ctrl+V в поле — картинка из буфера (скриншот Win+Shift+S,
  PrtSc) или скопированные в проводнике файлы, перетаскивание файлов на
  поле. Картинки (PNG, JPEG, GIF, WebP, до 3,75 МБ) модель получает
  изображением — нужна модель с поддержкой картинок; текстовые файлы
  (логи, XML, CSV, выгрузки; UTF-8 или Windows-1251, до 200 тыс. символов) —
  текстом. Документы — их текстом: Word (.docx), Excel (.xlsx, листы —
  строками через табуляцию, даты — датами), PowerPoint (.pptx, по
  слайдам), LibreOffice (.odt, .ods, .odp) и PDF (кроме сканов и
  зашифрованных); файл до 30 МБ, текст длиннее 200 тыс. символов
  обрезается с пометкой. Старые .doc, .xls, .ppt пересохраните в новый
  формат. Вложения видны на панели над полем («×» — убрать), в ленте —
  миниатюрами картинок (щелчок — открыть целиком) и строкой «Вложения:»,
  сохраняются в истории чата.
- **Файлы в ответе**: попросите документ или файл («сделай инструкцию в
  Word», «выгрузи остатки в Excel», «сделай презентацию») — модель
  приложит его к ответу (инструмент `attach_file`): под ответом карточка
  со значком, именем и размером, «Сохранить…» и «Открыть» (программой
  системы). Форматы:
  - Word (.docx) — из Markdown модели: заголовки, списки, таблицы,
    цитаты, код, ссылки;
  - Excel (.xlsx) — каждая таблица — свой лист (имя из заголовка над
    ней), числа и даты `ДД.ММ.ГГГГ` — числами и датами, формулы `=SUM(…)`
    считаются, шапка закреплена, с автофильтром; можно и из CSV;
  - PowerPoint (.pptx) — заголовок `#`/`##` начинает слайд, первый —
    титульный; пункты, таблицы, код; 16:9;
  - CSV (с BOM, чтобы Excel узнал кириллицу), .txt, .md, .xml, .json,
    .html, .bsl — как есть.

  PDF — нет: модель предложит .docx, из Word его можно сохранить в PDF.
  Файлы хранятся в истории чата; модели содержимое файла дальше не
  отправляется.
- **Скиллы** — проверенные инструкции для типовых задач. Вызов —
  `/имя [что сделать]` (список появляется после `/`), а модель и сама
  читает подходящий скилл (инструмент `skill`), если задача под него
  подходит. Встроенные:
  - стиль и проверка кода: `/bsl-style` (стиль кода — без защитного
    обвеса и лишних комментариев, имена не совпадают со свойствами формы),
    `/query-style` (стиль запросов — точка вместо лишних соединений,
    временные таблицы вместо подзапросов), `/code-standards` (проверка
    модуля на стандарты), `/query-optimize` (медленный запрос),
    `/client-server` (серверные вызовы в формах), `/method-docs`
    (комментарии к методам), `/posting` (обработка проведения);
  - проект и база: `/edt-project` (проверка после правки через EDT MCP,
    метаданные файлами), `/live-base` (живая база через MCP-серверы 1С),
    `/release-update` (версии, обработчики обновления, слияние веток);
  - темы: `/access-rights` (роли, профили, РЛС, привилегированный режим),
    `/html-field` (поле HTML документа), `/platform-gotchas` (грабли
    платформы, БСП, Документооборота);
  - `/commit-message` (текст коммита, им пользуется «Сообщение коммита»),
    `create-skill` (как писать скиллы).

  `/skills` или «Скиллы…» в меню вида — окно со всеми скиллами: галочка
  включает и выключает скилл (выключенный модель не видит и командой его не
  вызвать), внизу — текст выбранного, кнопка «Открыть папку своих…». Свой
  скилл: `/skill <описание>` — модель напишет инструкцию и сохранит
  (`save_skill`). Скиллы проекта — файлы `.md` в
  `<проект>/.edtai/skills/` (общие для команды через git); формат —
  заголовок `---` с `name:` и `description:`, дальше инструкция в
  Markdown. Свой и скилл проекта с тем же именем заменяют встроенный.
- **Название чата** после первого ответа придумывает модель (2–6 слов,
  один короткий запрос); переименованный вручную чат не трогается.
  Выключить — настройка рабочей области `generateChatTitles=false`.
- **«Только вопросы»** — флажок справа от строки состояния (и `/readonly`):
  модель не получает инструменты, меняющие проект (`edit_module`,
  `git_restore`, инструменты MCP с `readOnlyHint: false`, а без подсказки
  сервера — все, чьё имя не начинается с читающего глагола: `get_`,
  `list_`, `read_`, `search_`, `find_`…), и правки показывает кодом в
  ответе. Действует во всех чатах.
- **Строка состояния** под полем ввода: пока идёт ответ — что делает
  модель («думает… 12 с», «пишет ответ…», «Читает модуль …»); после — «контекст
  45k из 200k · ответ ↑120k ↓2,1k»: сколько окна модели занято и сколько
  токенов ушло на ответ (со всеми шагами с инструментами). «≈» — сервер
  не прислал `usage`, это оценка по длине текста.
- **Window → Preferences → EDT AI:**
  - протокол: OpenAI-совместимый (`/v1/chat/completions`) или Anthropic
    Messages (`/v1/messages`);
  - адрес сервера и модель. Адрес можно указать как сервер
    (`https://сервер`), с версией API (`https://сервер/v1`) или полным
    адресом метода; кнопка **«Список…»** у поля «Модель» загружает модели
    сервера (`GET /v1/models`) — выбрать из меню;
  - «Макс. токенов ответа» — пусто по умолчанию (для Anthropic — 8192, в
    OpenAI-совместимый не передаётся);
  - системный промпт — по умолчанию короткая инструкция про 1С и EDT,
    пустое поле — без системного промпта, «Restore Defaults» возвращает
    исходный;
  - «Лимит контекста, символов» — сколько кода из EDT прикреплять к одному
    сообщению (по умолчанию 40 000). Что не влезло, обрезается по строкам,
    фрагмент на панели помечается «обрезано». Тот же лимит — на результат
    одного вызова инструмента;
  - «Окно модели, токенов» — сколько модель принимает за раз вместе с
    ответом (`max_model_len` у vLLM, `num_ctx` у Ollama; по умолчанию
    32768). Если диалог не помещается, модели не передаются результаты
    старых шагов, код старых сообщений, потом самые старые сообщения — в
    ленте строка «Окно модели — …». К системному промпту плагин сам
    добавляет проект, конфигурацию, открытый модуль и метод под курсором;
  - «Инструменты» — разрешить модели читать проект и вызывать инструменты
    MCP-серверов (каждый вызов MCP — с подтверждением). Если сервер модели
    инструменты не поддерживает (например, vLLM без
    `--enable-auto-tool-choice`), плагин сам повторит запрос без них;
  - **«Проверить подключение»** — короткий запрос к модели с текущими
    значениями полей, до сохранения;
  - токен: сохраняется в Secure Storage, в обычные настройки не попадает;
  - сертификаты: доверять корневым сертификатам ОС (на Windows —
    хранилище `Windows-ROOT`, на Linux — `/etc/ssl/certs/ca-certificates.crt`)
    и дополнительный PEM-файл с корпоративным CA. Под полем видно, сколько
    сертификатов прочитано из файла;
  - MCP-серверы: имя, URL, какие инструменты давать модели, флажок
    «включён»; кнопка «Проверить» подключается и показывает, сколько у
    сервера инструментов. Пока только HTTP (Streamable HTTP), без токена.

## MCP: EDT-MCP

[EDT-MCP](https://github.com/DitriXNew/EDT-MCP) — MCP-сервер внутри EDT:
ошибки проекта, метаданные, модули, поиск ссылок, тесты. Текущие версии —
для EDT 2026.1+, для EDT 2025.x — версии до 1.26.1.

1. Поставьте EDT-MCP по его инструкции, в EDT: **Window → Preferences →
   MCP Server** — порт (по умолчанию 8765), автозапуск.
2. **Window → Preferences → EDT AI → MCP-серверы → Добавить…**: имя `EDT`,
   транспорт `http`, URL `http://localhost:8765/mcp`.
3. Поле **«Инструменты»** — у EDT-MCP их около сотни, и описание каждого
   уходит модели в каждом запросе. Для начала хватит чтения:

   ```
   get_edt_version, list_projects, get_configuration_properties, get_problem_summary, get_project_errors, get_metadata_objects, get_metadata_details, list_modules, read_module_source, read_method_source, get_module_structure, search_in_code, find_references, get_method_call_hierarchy, go_to_definition, get_symbol_info, get_platform_documentation, validate_query
   ```

4. **Проверить** — должно быть «Подключено: EDT MCP Server … Инструментов:
   …, модели доступно по фильтру: 18».
5. В чате: «Какие ошибки в проекте?», «Где вызывается процедура Х?». Перед
   каждым вызовом над полем ввода — вопрос: **Разрешить**, **Разрешать в
   этом чате**, **Авторежим** (больше не спрашивать, во всех чатах) или
   **Отклонить**. Авторежим включается и выключается кнопкой с молнией
   под полем ввода или командой `/auto`. Что вызывалось, видно в ленте
   строками «→ MCP «EDT»: get_project_errors — …».
6. Кнопка **MCP** в рамке ввода — индикатор: зелёная точка — все
   включённые серверы подключены, красная — какой-то не подключился,
   серая — серверов нет или ещё не проверялись (подсказка — по каждому
   серверу). Щелчок — окно `/mcp`. В ленте ошибки подключения не
   пишутся: ответ просто идёт без этого сервера.

## Подключение модели

Примеры настроек (протокол · адрес · модель · токен):

| Сервер | Протокол | Адрес | Токен |
|---|---|---|---|
| Ollama на своём компьютере | OpenAI-совместимый | `http://localhost:11434` | не нужен |
| LM Studio | OpenAI-совместимый | `http://localhost:1234` | не нужен |
| vLLM или корпоративный шлюз | OpenAI-совместимый | `https://<сервер>/v1` | если требует сервер |
| Anthropic API | Anthropic Messages | `https://api.anthropic.com` | ключ API |

Имя модели — как его знает сервер (`ollama list`, список моделей в LM Studio,
документация шлюза). Если сервер не отвечает, «Проверить подключение»
покажет причину: не найден хост, соединение отклонено, сертификату нет
доверия, неверный токен, неверный адрес метода и т. п.

Прокси берётся из настроек Eclipse (**Window → Preferences → General →
Network Connections**).

## Установка в EDT

1. В EDT: **Help → Install New Software…** → **Add…**, в поле **Location**
   — `https://hansglorias.github.io/EDT_AI/` (update site публикуется
   на GitHub Pages после каждого слияния в `main`). Обновления потом —
   **Help → Check for Updates**.

   Без доступа к GitHub — zip:
   - из GitHub Actions: последний успешный запуск **build**, артефакт
     `edtai-update-site`;
   - или соберите сами (см. ниже) и возьмите
     `releng/io.github.hansglorias.edtai.repository/target/io.github.hansglorias.edtai.repository-<версия>.zip`.

   В **Add…** тогда **Archive…** и выберите zip.
2. Нажмите **Add**.
3. Отметьте **EDT AI**. Если список пуст, снимите флажок **Group items by
   category**.
4. Снимите флажок **Contact all update sites during install to find required
   software**: всё нужное уже есть в EDT, а в закрытом контуре внешние сайты
   недоступны.
5. **Next → Next**, примите лицензию, **Finish**.
6. На вопрос о неподписанном содержимом ответьте **Install anyway**: плагин
   пока не подписан.
7. Перезапустите EDT.

Если **Install New Software** недоступен (например, его отключили
политикой), можно поставить через dropins: распакуйте zip, скопируйте jar из
`plugins/` в каталог `dropins/` рядом с исполняемым файлом EDT и
перезапустите EDT.

### Закрытый контур

- Перенесите zip любым разрешённым способом. Плагин ничего не скачивает при
  установке и не требует доступа в интернет.
- Корпоративный CA: Preferences → EDT AI → **Файл CA (PEM)**. Файл может
  содержать несколько сертификатов. Если CA уже установлен в систему,
  достаточно флажка **Доверять корневым сертификатам операционной системы**.
- Токен хранится в Eclipse Secure Storage. На Windows он защищён учётной
  записью пользователя. На Linux, если нет связки ключей (libsecret), EDT
  при первом сохранении попросит задать мастер-пароль Secure Storage.

### Если Install New Software падает: EDT в `/opt`, sudo нет

Так бывает на Linux, когда EDT установлена от root. Ошибки: «Ошибка при сборе
элементов для установки» или «Ошибка при установке элементов». Через Install
New Software в такой EDT не встаёт ни один плагин. Обходной путь без p2 и без
прав на каталог EDT — скрипт
[`tools/edtai-user-install.sh`](tools/edtai-user-install.sh):

```bash
bash edtai-user-install.sh /tmp/edtai.zip /opt/1C/1CE/components/1c-edt-<версия>
```

```bash
bash ~/.edt-ai/edt.sh
```

Пошаговая инструкция, разбор причин и что может исправить администратор —
в [docs/install-astra.md](docs/install-astra.md).

### Удаление

**Help → About → Installation Details → Installed Software → EDT AI →
Uninstall.**

## Сборка

Нужны JDK 17 и доступ к `download.eclipse.org` и Maven Central. Maven
отдельно ставить не нужно: `mvnw` / `mvnw.cmd` скачает проверенную версию
(3.9.11). На Windows вместо `./mvnw` — `mvnw.cmd`.

```bash
./mvnw -B verify
```

На Linux без дисплея UI-тесты запускаются так:

```bash
xvfb-run -a ./mvnw -B verify
```

Сборка без тестов:

```bash
./mvnw -B verify -DskipTests
```

Структура проекта:

| Каталог | Что внутри |
|---|---|
| `releng/edtai.target` | target platform: Eclipse 2023-12 (4.30) |
| `bundles/…core` | настройки, Secure Storage, TLS, JSON, клиент модели, диалог; без UI |
| `bundles/…ui` | вид «EDT AI», страница настроек |
| `tests/…core.tests` | тесты ядра (JUnit 5, OSGi без UI) против фейкового сервера модели |
| `tests/…ui.tests` | тесты вида и настроек в живом workbench, скриншоты |
| `features/…feature` | фича для установки |
| `releng/…repository` | update-site (p2) и его zip |

CI (GitHub Actions) собирает и тестирует на Ubuntu (GTK под xvfb) и Windows.
UI-тесты сохраняют снимки вида и настроек в `tests/…ui.tests/target/screenshots/`,
в CI они лежат в артефакте `screenshots-<ОС>`.
